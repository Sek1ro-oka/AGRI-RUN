## 1. 它是什么、能做什么

路线工坊是一个**位置模拟**工具：你在地图上画出路线，它把模拟位置按设定的速度和圈数投给系统，让**其他应用**（运动、打卡、导航等）相信你正在沿这条路线移动。

它能做：

- 地图点选或手输经纬度画路线，支持撤销、清空、闭合/开口、到终点停止或原路往返
- 按"行走 / 跑步 / 骑行"三档配速运行，运行中可随时改速（位置不跳变）
- 只发一个固定的单点（速度 0），或点地图任意位置瞬移过去
- 悬浮控制条：切到别的应用时也能暂停/继续/停止，并按 A/B/C 三个预设点一键传送
- 路线存本地、导出/导入 GPX
- 诊断页把"系统到底收没收到"变成可核对的数字；另有一个独立的"定位探针"App 做交叉验证

它**不能**做（截至 0.3.2）：

- 不能改真实 GPS 硬件读数。它走的是 Android 的 **mock location（模拟位置）** 机制，必须在开发者选项里把本应用选为"模拟位置信息应用"，否则系统直接拒收。
- 不能保证每个目标 App 都采信。有的 App 会检测 `isMock()` 标记、有的只读 Google Play services 融合定位，需要按第 16 章逐通道验证。
- 没有卫星图、没有地点搜索、没有云端账号。

## 2. 名词表

| 名词 | 含义 |
| --- | --- |
| 节点 | 路线上的一个经纬度点，两个以上才能运行 |
| 单程 / 单圈 / 往返 | 开口路线首点到末点的长度 / 闭合路线的整圈长度 / 原路往返一次的总长度 |
| 闭合 | 末点是否连回第一个点。默认**不闭合** |
| 到终点 | 跑完之后的动作：`停止`（单程，只跑一次）或 `原路往返`（按往返计圈） |
| 圈数 | 重复次数。开口单程固定为 1；往返与绕圈可 1–1000 |
| 有效用时 | 只累计"运行中"的时间，暂停期间不计 |
| provider | Android 系统里的位置来源：`gps`、`network`、`fused`（平台融合） |
| FLP | Google Play services 的 `FusedLocationProviderClient`，与 `fused` provider 是**两条不同**的通道 |
| 瓦片源 | 底图从哪个服务器取图（高德 / 腾讯 / OSM 系列） |
| GCJ-02 / WGS-84 | 国内加密坐标系 / 国际标准坐标系。**应用内部一律存 WGS-84**，只有画高德、腾讯底图时才在显示层换算 |

## 3. 安装与首次启动

### 3.1 自己构建安装包

在工程根目录（`route-workshop/`，Windows 用 `gradlew.bat`）：

```bat
:: 主应用（release）
gradlew.bat :app:assembleRelease --console=plain
:: 定位探针（debug 就够）
gradlew.bat :location-probe:assembleDebug --console=plain
```

产物：

| 文件 | 路径 |
| --- | --- |
| 主应用 | `app/build/outputs/apk/release/app-release.apk`（0.3.3 实测 73,185,200 B ≈ 69.8 MiB，debug 签名体系下体积偏大属正常） |
| 定位探针 | `location-probe/build/outputs/apk/debug/location-probe-debug.apk`（0.1.4 实测 12,736,975 B ≈ 12.1 MiB） |

`app-release.apk` 用本地自签名（未配置正式签名密钥），因此**不能覆盖安装**别的机器签出来的包，升级前先卸载旧版。

高德 Key 从 `local.properties` 的 `amapKey=...` 注入 `BuildConfig.AMAP_KEY`，不进仓库；没配 Key 时自动走栅格瓦片，功能不受影响。

### 3.2 装到手机

1. `adb install -r app-release.apk`（或把 APK 拷到手机点安装，需允许"安装未知应用"）。
2. 需要探针时同样装 `location-probe-debug.apk`。

### 3.3 首次启动必须准备的四件事

打开 App → 右上角菜单 → **设置检查**，按页面顺序逐项过：

| 检查项 | 正常的标志 | 不通过怎么办 |
| --- | --- | --- |
| 定位权限（精确位置） | 已授权 | 弹窗选"使用应用时允许"+ 打开"精确位置"；已拒过就到应用详情 → 权限里改 |
| 通知权限（Android 13+） | 已授权 | 不授权也能跑，但通知栏看不到暂停/停止按钮 |
| 系统定位开关 | 已开启 | 下拉快捷开关打开"位置信息" |
| 开发者选项中的模拟位置应用 | 页面会写"需确认" | 设置 → 关于手机 → 连点"版本号"7 次开启开发者选项 → 开发者选项 → **选择模拟位置信息应用** → 选"路线工坊" |

页面底部还有两个按钮：

- **检测模拟位置权限**：创建一个测试 provider 并立刻移除，用来当场判断系统是否真的允许本应用提交模拟位置。**运行任务中不要点**（会把测试 provider 插进正在用的会话里）。
- **打开开发者选项 / 打开应用详情**：直达对应系统页面。

四项里有任何一项是"失败"，模拟位置一定不会生效——先修环境，再谈路线。

## 4. 五分钟上手

目标：让一个其他应用看到你在地图上"走"了一段路。

1. **准备**：按 3.3 过一遍设置检查，四项都正常。
2. **加两个点**：在地图上点两下（拖动、双指缩放不会加点）。左上角提示条写着"点击地图添加节点；拖动与双指缩放不会添加节点"。
3. **选配速**：点"行走"（默认 5.0 km/h），速度输入框会自动填上。
4. **圈数**：填 `1`。开口路线会自动固定为 1。
5. **开始**：点"开始"。首次会申请定位权限；通知栏出现常驻通知。
6. **看状态**：控制区"状态"变"运行中"，"有效用时"开始走，"当前位置"和"累计距离"随之变化，"已提交给"显示系统接受了哪些 provider。
7. **验证**：切到目标应用看它是否在动；不确定就用探针（第 16 章）。
8. **停止**：点"停止"。模拟位置被撤销，系统恢复真实定位。

> 想先确认"到底通了没有"再去折腾目标 App：跑起来后回 App 菜单 → 诊断信息，看"位置自检"那一栏。它会告诉你系统最后读回的位置、是不是带模拟标记、距今多少秒。

## 5. 主界面逐区说明

界面从上到下是四块：

### 5.1 顶部工具条

标题"路线工坊"，右侧"⋮"是全部功能入口（见第 6 章）。

### 5.2 路线选项行（工具条正下方，地图上方）

| 控件 | 作用 |
| --- | --- |
| 复选框"将当前末点连接到第一个点" | 闭合开关。**默认不勾**（末点不连回起点）。勾上就是绕圈 |
| 右侧"单程 / 单圈 / 往返 … 米" | 随点数与闭合状态实时计算的路线长度 |
| "到终点" + 两个单选项：**停止** / **原路往返** | 跑完之后的动作。开口+停止 = 单程只跑一次；开口+往返 = 到末点掉头回起点，按往返计圈；闭合时随时长按圈数绕圈 |

### 5.3 地图区

- 手指**点一下 = 加一个节点**；拖动平移、双指缩放**不会**误加点。
- 左上角浮动提示条（始终显示）。
- 底部红色状态条：地图样式/瓦片加载失败、超时、退回到瓦片引擎等信息会出现在这里，平时隐藏。
- 顶部路线是橙色折线，起点有独立标记，运行中的位置是另一个标记；地图默认跟随当前位置（拖动后会暂停跟随，点"定位到当前位置"恢复）。

### 5.4 控制区（地图下方）

按顺序：

1. **状态 / 有效用时**：状态取值为 空闲、就绪、启动中、运行中、已暂停、已完成、已停止、出错。
2. **速度 / 单圈**：当前速度、单圈长度。
3. **累计距离 / 已完成圈数**。
4. **当前位置 / 已提交给**：`已提交给` 列出系统实际接受的 provider，是"有没有通"的第一手证据。
5. **速度（km/h）/ 圈数** 两个输入框：速度范围 **0.5–60**，圈数 **1–1000**。
6. **配速（长按可改）：行走 / 跑步 / 骑行**：默认 5.0 / 9.0 / 15.0 km/h。点一下填入速度框；运行中点击会直接把新速度下发给前台服务（提示"已改速为 X km/h（位置不跳变）"）。长按弹窗改这一档的值，可"恢复默认"。
7. **撤销 / 清空 / 手动输入**：撤销删掉最后一个节点；清空会二次确认"将删除当前草稿的全部节点"；手动输入弹窗直接粘坐标。
8. **开始 / 暂停 / 继续 / 停止**：同一时刻只允许一个任务，重复点"开始"只提示不新建。
9. 最底一行灰字提示：随状态给出下一步建议（例如"已有运行任务，先停止"）。

## 7. 画一条路线

### 7.1 点选加点

- 点一下加一个节点；**与上一个节点重合**的点会被拒绝（提示"与上一个节点重合，或已达 5000 个节点上限"）。
- 单条路线上限 **5000 个节点**。
- 撤销一次删一个节点，没有"重做"。

### 7.2 手动输入

"手动输入"弹窗接收一行文本，格式：

```
纬度, 经度
30.123456, 120.123456
```

- 坐标一律 **WGS-84**、**纬度在前**，逗号分隔。
- 用于把别人给的坐标直接贴进来，或精确定位到某个点。

### 7.3 长度显示的含义

| 组合 | 长度文案 | 运行时怎么走 |
| --- | --- | --- |
| 不闭合 + 到终点停止 | 单程 X 米 | 从首点走到末点，**只跑一次**，圈数自动固定为 1 |
| 不闭合 + 到终点原路往返 | 往返 X 米（单程 Y 米） | 首点→末点→首点算一圈，按圈数重复 |
| 闭合（勾了复选框） | 单圈 X 米 | 末点连回首点，按圈数绕圈，到终点策略此时不起作用 |

## 8. 闭合开关与"到终点"策略

这是 0.2.0 之后变化最大、也最容易误解的一处：

- **默认不闭合**：新建路线是开口的，画到哪算到哪，不会再偷偷把末点连回起点。
- **不闭合不等于"原路返回"**。要原路返回必须显式把"到终点"选成**原路往返**；选**停止**就是单程跑一次。
- 旧版本（0.1.x）保存的路线文件在加载时会按旧的"闭合"字段迁移：`closed=true` → 绕圈，`closed=false` → 原路往返。也就是说**老文件行为不变**，不会被悄悄改成单程。

## 9. 开始运行：状态与各字段含义

点"开始"的前置条件：

- 已有至少 **2 个不同节点**（否则提示"至少需要 2 个不同的节点才能运行"）
- 没有正在进行的任务（单会话）
- 精确位置权限已授予

状态流转：

| 状态 | 含义 |
| --- | --- |
| 空闲 | 没有任务，草稿可编辑 |
| 就绪 | 参数已通过校验 |
| 启动中 | 前台服务起来、正在创建模拟 provider |
| 运行中 | 正常投递位置 |
| 已暂停 | 位置停在最后一点，**有效用时停止累计** |
| 已完成 | 圈数跑满正常结束 |
| 已停止 | 用户主动停止（或任务被系统杀掉后收尾） |
| 出错 | 见通知/诊断页的错误码与消息 |

运行期间建议把 App 放前台或开悬浮条：Android 12+ 对后台限制严格，但本应用用的是**前台服务**（通知栏常驻），正常情况下切到别的应用也能继续。

字段读法：

- **有效用时**：只算运行中的时间，暂停不计（`ActiveElapsedClock`）。
- **单圈**：当前策略下单圈长度，与路线选项行一致。
- **累计距离**：本任务累计投递的位移。
- **已完成圈数**：往返/绕圈下每完成一圈 +1。
- **已提交给**：系统实际接受的 provider 名单。如果这里是空的或只有一部分，说明该通道没通，去第 16 章逐条对。

## 10. 改速度的三种办法

1. **直接改输入框**：填 0.5–60 的数字，点"开始"时生效。
2. **点配速按钮**：行走 / 跑步 / 骑行，填入输入框；任务运行中点击**立即生效**。
3. **长按配速按钮**：弹窗改这一档的数值（例如把"跑步"从 9.0 改成 10.5），可"恢复默认"。三档值会持久保存。

运行中改速的关键特性：**位置不会跳变**。内部按距离分段累计（`DistancePhase`），换速只改变之后每帧前进的长度，不会因为"按新速度重算已过时间"而瞬移。提示语就是"已改速为 X km/h（位置不跳变）"。

没有任何任务时点配速，只填输入框，提示"当前没有运行中的任务，已填入 X km/h"。

## 11. 单点、传送、定位、快捷传送点

### 11.1 发送单点位置

菜单 → 发送单点位置 → 输入纬度（-90~90）、经度（-180~180）→ 发送。

效果：前台服务把位置**固定在这一点、速度 0**，直到点"停止"。适合"让人以为我一直在家/在公司"这类静态场景。

限制：已有任务时必须先停止（提示"已有运行任务，请先停止再发送单点位置"）。

### 11.2 传送到地图选点

菜单 → 传送到地图选点 → 在地图上点目标位置。

- 点中的瞬间模拟位置就搬过去（复用单点模式，速度 0，可随时停止）。
- 再点一次同一菜单项即取消选点模式。
- 同样要求当前没有运行中的任务。

### 11.3 定位到当前位置

把地图视野拉回当前模拟位置，并恢复"跟随"。手动拖动地图后会停止跟随，用这项恢复。

### 11.4 设置快捷传送点（悬浮条的 A / B / C）

菜单 → 设置快捷传送点，弹窗里对 A、B、C 各有两个动作：

- **设为 A**：取"草稿的最后一个节点"，没有节点时退回"地图中心视野点"。
- **清除 A**。

地图还没定位过（当前是 0,0）时会提示"先加一个节点，或把地图拖到目标区域"。

设置完成后，运行中（或未运行时）都可以在悬浮条上点 A/B/C 一键传送。0.3.2 起**路线任务运行中点 A/B/C 也生效**：服务会就地切成单点任务（位置立刻跳到槽位并钉住、速度归零），不需要先停止，传送时 toast「已发送传送命令：A」。

0.3.3 起这条路径按"传送前的状态"分三种情形（规则固化在 `TaskModeSwitch`）：

| 传送前的状态 | 传送后 | 说明 |
| --- | --- | --- |
| 运行中 | 继续运行（单点） | 不会因为传送把任务打断；有效用时从传送那一刻重新累计 |
| 已暂停 | 仍然暂停（单点） | 传送**不会**自动恢复任务，已累计的有效用时保留 |
| 启动中 | 转成运行中（单点） | 唯一会推进状态机的分支 |

0.3.3 还修了一个"传送后发布节奏变快"的问题：现在同一个 Handler 上最多只有一个待执行的发布 tick，连续点 A/B/C 十几次也不会出现多个循环并行。

## 12. 悬浮控制条（跨应用）

### 12.1 开启

1. 菜单 → 悬浮控制条（跨应用）。
2. 若还没授权，会提示"需要先授予「显示在其他应用上层」权限"，弹出系统授权页，允许即可。
3. 再点一次菜单即关闭（菜单项可勾选，勾上=开启）。

### 12.2 它长什么样、能做什么

一条浮在别的应用之上的小面板：

- 状态行：`运行中 / 已暂停 / 准备中 · 9.0 km/h · 1234 m`
- 按钮：**暂停 / 继续 / 停止**
- 按钮：**A / B / C** 三个快捷传送点（未设置时提示"槽位 A 还没设置点位：回到应用，菜单「设置快捷传送点」"）
- 可以按住空白处拖动到顺手的位置；拖动时被夹在屏幕内，松手后位置会记住，下次按键位出现

### 12.3 0.3.2 起的行为（0.3.3 补上后台刷新）

- 悬浮条**常显**（菜单里开着、系统允许悬浮即可），不再要求任务正在运行。未运行时状态行显示
  「未运行 · 点 A/B/C 可传送到槽位」，暂停/停止按钮变灰。
- 冷态直接点 A/B/C 会启动一个单点任务并传送到槽位——这就是"在别的应用里直接把人送过去"。
- 路线任务运行中点 A/B/C 现在**生效**：就地切成单点任务，不重启服务、不重建 provider，位置立刻跳过去。
- 拖动每帧夹在屏幕内；松手写入偏好，下次恢复原位。
- **0.3.3 起悬浮条与主界面彻底解耦**：状态订阅不再挂在主界面的生命周期上。把主界面切到后台、甚至旋转屏幕，悬浮条都会继续刷新（冷态点 A 之后会立刻变成"单点位置"、停止按钮可点）。关掉悬浮条时订阅成对注销，反复开关不会出现两个窗口或两条订阅。

## 13. 路线保存、加载与 GPX

### 13.1 本地路线库

- 保存路线：把当前草稿写成本地 JSON（含点数、闭合状态、到终点策略、圈数/速度的"下次预填值"）。
- 加载路线：列表按名称列出，点选即加载。
- 重命名 / 删除：作用于已保存的路线。
- 存储位置：应用私有目录 `files/routes/<id>.json`（见第 20 章）。

> 0.3.2 起保存带编辑代次：保存期间你又改了草稿，完成后会提示"保存期间又有编辑，请再保存一次"，不会再把改动当成已保存（N-04 已修）。
> 0.3.3 起令牌还包含"草稿代次"：保存 A 的过程中切到 B（哪怕 B 一个字都没改），旧回调也不会把 B 标成已保存。

### 13.2 导出 GPX

菜单 → 导出 GPX 到文件 → 系统文件选择器里定位置和文件名。

- 至少 2 个节点才能导。
- 默认文件名是路线名（非法字符与空白替换成 `-`），名字为空则用"路线 + 时间戳"。
- 输出是标准 GPX 1.1：`<trk><trkseg><trkpt .../></trkseg></trk>`，坐标为 WGS-84。

### 13.3 导入 GPX

菜单 → 从 GPX 文件导入 → 选文件。

行为与限制：

- 认可 `trkpt`、`rtept`、`wpt` 三种点元素。
- **多段轨迹只取第一段** `<trkseg>`，并提示"文件含 N 段轨迹……只导入第一段"。
- **不弹预览，直接替换当前草稿的全部节点**（路线 ID、名称、闭合开关保持你当前的选择）。
- 限制说明：`<wpt>`（航点）和 `<rte>` 里的点仍会按文档顺序混进路线，可能与轨迹点不一致；如果你导入的文件同时含轨迹和航点，导入后请用"撤销/清空"或手工整理。

## 15. 诊断信息页

菜单 → 诊断信息。自上而下：

1. **记录坐标日志（默认关闭）**：打开后才会把坐标写进日志（默认关闭是为了隐私与性能）。
2. **启用 Google Play services 模拟位置（第二条输出通道）** + 状态行：开启后，除了 Android 系统的 mock provider，还会尝试通过 GMS FLP 的模拟接口投递位置。**下次运行生效**。设备没有 Play services 时会显示 `UNAVAILABLE（状态码 …）`。
3. **位置自检**：显示"应用最后提交 X（时间）"以及各 provider 实际读回的内容与结论（有没有模拟标记、几秒前）。这是判断"通没通"最快的地方。
4. **报告文本**：分段为【应用】【系统】【权限】【定位服务】【运行状态】【路线库】【最近日志】，包含包名版本、机型、Android 版本、构建指纹、权限状态、三个 provider 是否支持、runId、位置、单圈/累计、圈数、有效用时、已提交给、错误码、路线库路径与条目、最近日志。
5. **复制全部** / **清空日志**：把报告贴进问题记录用。

日志只在内存里保留最近 200 行，杀进程即丢；需要落盘请开坐标日志并用 `adb logcat`（第 19 章）。

## 16. 定位探针（四通道验证）

### 16.1 它解决什么问题

"探针说收到了、目标 App 却不动"是最常见的误判。原因是：同一次模拟位置提交，不同 API 的读取路径不同。探针用**独立包名**（`org.localroute.probe`）、**只走系统公开接口**去逐条读取，把"收到了吗"变成数字。

### 16.2 通道

| 通道 | 读的是什么 | 谁会这么读 |
| --- | --- | --- |
| `gps` | `LocationManager` 的 GPS provider | 直接要 GPS 的跑步/计步 App、老应用 |
| `network` | `LocationManager` 的 NETWORK provider | 只要粗略位置的应用 |
| `fused(framework)` | `LocationManager` 里名为 `fused` 的平台融合 provider | 用 Criteria/融合定位的客户端 |
| `gms-flp` | Google Play services 的 `FusedLocationProviderClient` | 绝大多数现代运动/导航 App |
| `amap-sdk` | 高德定位 SDK（`mockEnable=false`，复现目标 App 的接收策略） | 用过 `AMapLocationClient` 的国内 App |
| `amap-sdk-dev` | 高德定位 SDK（`mockEnable=true`，开发对照） | 只用于对照，不对应任何真实配置 |

另外还有第 7 条 `criteria`：按"精度高、要速度/航向、低功耗"的条件让系统自己挑 provider，并打印"挑中了谁"，用于复现按条件选源的行为。所以准确说法是**四条主通道 + 两条高德通道 + 一条诊断信息**。

高德两条通道是 0.3.2 加的，0.3.3 修好了对照：`setLocationPurpose(Sport)` 会把之前设的 `mockEnable` 覆盖掉，
所以对照通道现在是**先**套场景、**最后**才 `setMockEnable(true)`；报告里两条通道各自打印 getter 实读值，
并附一行 `自检：主通道 mockEnable=false ✓，对照通道 mockEnable=true ✓`。看到 ✗ 就说明对照无效，别拿它下结论。

### 16.3 怎么用

1. 装机后打开"定位探针"，授予定位权限。
2. 点"**开始监听**"。日志区会逐条打印每个通道的订阅结果：`已订阅` / `UNAVAILABLE（provider 不存在或未启用）` / `PERMISSION_DENIED`。
3. 让主应用开始跑任务（或发单点/传送）。
4. 看日志里四条通道是否都在刷帧，每帧显示：时间、通道、与上一帧的间隔、经纬度、精度、位置年龄、速度/航向、是否标记模拟。
5. 点"**停止**"，底部会打印"各通道汇总"，每条通道一行：

```
gps：回调 312 次（有效 312 / 错误 0），首帧延迟 480 ms，间隔 中位 500 ms / P95 520 ms / 最长 640 ms，
     位移 1246.3 米（位置跳变累计，不是运动距离），均速 2.49 m/s，模拟标记 312/312，位移速度比 0.99
```

高德通道出错时会是这样（错误回调**不**计入位移与均速，这一点 0.3.3 才修）：

```
amap-sdk：回调 27 次（有效 0 / 错误 27），首帧延迟 210 ms，间隔 中位 1000 ms / P95 1005 ms / 最长 1010 ms，
         位移 0.0 米（位置跳变累计，不是运动距离），均速 未提供（目标未给速度字段），模拟标记 0/0，位移速度比 无
```

6. 点"**复制报告**"，整段报告进剪贴板，可直接贴进问题记录。

### 16.4 报告怎么判读

只看五件事：

1. **有没有帧**：`0 个位置（没有收到回调）`= 这条路径没通。
2. **间隔**：中位接近 500 ms 说明按节奏在送；明显更大是客户端降采样（正常）；**最长间隔**突然变大才是断流。
3. **模拟标记 X/Y**：X 必须等于 Y。出现"未标记模拟"说明拿到的不像是我们投的。
4. **位移**：9 km/h 跑 60 秒约 150 米，不涨就是没在更新。
5. **位移速度比**：接近 1 说明速度字段与实测位移自洽（抖动、暂停帧会让它偏离，只是参考）。
6. **有效 / 错误回调**：高德通道会把 SDK 明确拒收的帧单列成"错误"。错误 27、有效 0 时，
   正确结论是"这条通道被 SDK 拦下了"，**不是**"它走了 595 米"。
7. **最后回调 N 秒前**：报告里每个通道都带这一项，用来判断是不是"早就断流了，只是我没注意"。

### 16.5 重要注意事项

0.3.1 起探针**离开页面不再停止监听**（`onStop` 只写一行提示，`onDestroy` 才停订阅），所以可以：

- 打开探针 → 点"开始监听" → 切到目标 App → 目标 App 全程运行 → 回到探针看汇总，这期间订阅一直有效；
- 若 ROM 在后台杀进程（部分厂商策略），回到探针会看到帧数在切走后不再增长，这时改用**分屏**把两者同时留在前台；
- 0.3.1 之前（探针 0.1.0）仍是"一离开就停"，只能分屏。

0.3.2 起报告多了两件事：

- **统计会话**：报告第一行会写清这是「传送测试」（只点 A/B/C）还是「跑步路线」。界面上有个
  「本次是传送测试」复选框，勾上就按传送的措辞输出——纯传送测试的位移一栏是"位置跳变累计"，
  本来就不该当运动距离看（27 帧 595 米、均速 0.00 m/s 是正常的）。
- **起止时间**：`起止时间：14:02:11 → 现在（83 秒，仍在监听）`，配合各通道的"最后回调 N 秒前"，
  能区分"没收到"和"收到过但断了"。

0.3.3 起错误回调与有效帧分开统计（见 16.3 的第二段示例），均速在没有速度样本时显示
「未提供（目标未给速度字段）」而不是 `0.00 m/s`。

## 17. 地图与瓦片源

菜单 → 地图瓦片源，5 个选项：

| 源 | 坐标系 | 说明 |
| --- | --- | --- |
| 高德地图（默认） | GCJ-02 | 国内直连通常最快；非官方公开瓦片接口，可能失效 |
| 腾讯地图 | GCJ-02 | 高德的备选，同样是非官方接口 |
| OpenStreetMap 官方 | WGS-84 | 国内可能 TLS 握手失败导致空白底图 |
| OSM France（备用） | WGS-84 | 备用镜像 |
| OSM Germany（备用） | WGS-84 | 备用镜像 |

要点：

- **存储与计算永远是 WGS-84**，只在画 GCJ-02 底图时做显示层换算；切源不会改你的数据，也不会丢点（切源时路线会重绘，已修）。
- 选中高德时会弹一句说明。只要 `local.properties` 里配了 `amapKey` 且设备 ABI 有对应的 so，应用会自动改用高德官方 3D SDK 渲染；SDK 初始化失败才回退瓦片。0.3.2 起这句文案已改为「设备 ABI 支持时用高德官方 SDK 渲染，不支持时自动回退栅格瓦片」，不再出现"官方 SDK 适配层待接入"这种过时说法（21 章 N-08）。
- 样式/瓦片加载 10 秒无响应会被判失败并提示原因（红色状态条）。常见原因是网络不通或被运营商劫持 → 换一个源即可。
- 没有卫星图、没有图层切换。

## 18. 常见问题排查

### 18.1 状态"运行中"，但目标 App 不动

按顺序查：

1. 设置检查四项是否全绿，尤其"模拟位置应用"这项（用"检测模拟位置权限"实测）。
2. 诊断页"位置自检"是否显示带**模拟标记**、且时间是**几秒前**（超过 10 秒就不正常）。
3. 探针四通道：哪几条有帧？如果只有 `gps` 有、`gms-flp` 是 0，说明目标 App 走 FLP → 到诊断页打开 **GMS FLP 通道** 再跑一次。
4. 目标 App 可能本身在拒绝 mock 位置（部分健康/打卡类应用会检测）。这种只能换 App 验证，工具侧无法绕过。

### 18.1.1 目标 App 地图在动，却始终不累计里程（0.3.1 重点）

这种情况不是"位置没送到"，而是"送到的帧被对方当成噪声或未进入记录流程"。按顺序做：

1. 先跑够时长：15 km/h 连跑 **3–5 分钟、位移 ≥ 1 km**（很多 App 要几百米才开累计）。
2. 还是 0：菜单 → **兼容性：发送间隔** → 选 **2000 毫秒**，速度提到 30–40 km/h，再跑 2 分钟。15 km/h + 500 ms 一帧只有约 2.1 米，小于声明的 3 米精度，容易被距离滤波丢掉；2000 ms 一帧约 8 米。
3. 看诊断页第一行「发布字段（每帧一致）」确认精度与卫星数已发；若同时出现"每帧位移小于声明精度"的 warning，就是上面第 2 条的场景。
4. 目标 App 弹出"检测到模拟位置/成绩无效"即判定为对方反作弊，工具侧不再继续尝试。

完整证据与判定表见 `docs/12_目标App里程不累计_排查与修改.md`。

### 18.2 "已提交给"是空的 / 缺 provider

- 空：模拟 provider 没创建成功，回设置检查看模拟位置权限；看诊断页错误码。
- 只有 `gps`、没有 `fused`：设备/ROM 不提供平台融合 provider，属正常，`gps` 通了就行。
- `gms-flp` 显示 `UNAVAILABLE（状态码 …）`：没装 Google Play services 或版本不匹配（国产 ROM 常见），该通道不可用，不代表其他通道不行。

### 18.3 底图空白 / 一直"地图加载中…"

换瓦片源（先试高德 → 腾讯 → OSM France）。仍然失败看红色状态条给出的原因，通常是 DNS/证书问题。

### 18.4 悬浮条不出现

- 是否授予了"显示在其他应用上层"。
- 菜单里"悬浮控制条（跨应用）"是否处于勾选状态。
- 0.3.2 起悬浮条常显；若仍看不到，重新开关一次菜单项。

### 18.5 点"开始"没反应 / 提示只有一行灰字

- 少于 2 个节点、或已有任务在跑。
- 权限刚被拒过：去应用详情重新授予"精确位置"。

### 18.6 暂停后"有效用时"不动

这是设计如此：暂停不计时。恢复运行后继续累计。

### 18.7 悬浮条拖没了

0.3.2 起位置会被记住、也被夹在屏幕内；真丢了就重新开关悬浮条，会回到默认位置。

## 21. 已知限制（会踩到的坑）

按严重程度排列，编号与仓库内的复盘记录一致：
