# 模拟器实测证据（0.1.3）

本目录的截图都来自 **Android 模拟器**（AVD：API 35 / x86_64 / 1080×2340），不是真机。
真我 GT Neo5 上的表现仍需用户自己复验；两者系统版本、ROM 与「模拟位置信息应用」实现不同，
不能相互替代。

运行环境：2026-10-27，Android 15（API 35）模拟器；主应用 `org.localroute.app.debug`
（versionCode 4 / 0.1.3，含 x86_64 ABI 的调试包）；探针 `org.localroute.probe`。

## 截图与它证明了什么

| 文件 | 操作 | 能证明什么 |
| --- | --- | --- |
| `01-首次启动-高德底图默认.png` | 清空应用数据后首次启动 | 默认底图是「高德地图（GCJ-02，非官方接口）」，首次进入就能看到中文道路与地名，不再是黑屏/空白 |
| `02-路线运行中-已提交gps与fused.png` | 两点路线 → 开始 | 状态「运行中」、速度 9.0 km/h、累计 39.7 m、有效用时 00:15、已完成 0/5 圈，底部写「已提交给 gps、fused」，红点正沿路线移动 |
| `03-探针收到模拟位置.png` | 主应用运行中，打开探针点「开始监听」 | 另一个应用（不同包名、独立清单）通过系统 API 读到 11 个位置、累计位移 12.6 米，每行都标「模拟位置」，坐标按 2.5 m/s 递增 —— 证明坐标确实进入了系统定位服务，而不是只在我们自己的界面里转 |
| `04-传送后当前定位.png` | 菜单「传送到地图选点」→ 点地图 | 传送模式按一次点击直接把当前模拟位置搬过去，界面显示新坐标，速度 0 |
| `05-OSM不可达提示.png` | 切到「OpenStreetMap 官方」 | OSM 瓦片取不到时，界面给出可见提示，而不是一片空白；路线与里程计算不受影响 |

| `07-两点自动取景.png` | 再加第二个节点 | 第二个点不在视野内时自动重新取景，两个节点与连线都在屏幕内 |
| `08-GCJ02对齐校验.png` | 输入 WGS-84 39.906297, 116.395157 | 该点在 GCJ-02 底图上正好落在「天安门东」地铁站图标上；若不做换算会偏出约 500 米，说明高德底图与 WGS-84 数据之间的换算是生效的 |
| `09-GPX导入结果.png` | 导出 GPX 后清空，再从同一文件导入 | 两点、单圈 1.02 km 与导出前一致，说明往返无损 |

## 系统侧读数（同一台模拟器，adb 采集）

主应用运行中：

```
last location=Location[gps 39.906032,116.394823 hAcc=3.0 ... vel=2.5 bear=224.04639 mock]
last location=Location[gps 39.906032,116.394823 ... mock]   # fused 读到同一帧
```

传送（单点模式，速度为 0）：

```
last location=Location[gps 41.484638,40.813211 ... vel=0.0 bear=0.0 mock]
```

`mock` 标记由系统写入；`gps` 与 `fused` 两个 provider 都收到了这些位置。

## 没能证明的事

- **真机是否一致**：真我 GT Neo5 的 ROM 可能对测试 provider 有额外限制（例如必须重启、必须重新选择模拟位置应用）。本目录的截图只覆盖 AOSP 行为。
- **长时间后台**：锁屏、切后台、灭屏 10 分钟的续航与更新表现没有在本轮重测（0.1.2 及以前的结构没变，仍以真机复验为准）。
- **高德瓦片接口的长期可用性**：这是非官方公开接口，今天可用不代表一直可用；不可用时请切回 OSM 或备用源。
- **国内网络下的 OSM**：模拟器里 OSM 域名解析到 10.112.4.179（黑洞地址）并 `SSLHandshakeException`，所以本机无法验证 OSM 源；这与国内常见网络状况一致，也是默认改用高德的原因。
