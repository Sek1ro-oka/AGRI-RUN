# 01 需求澄清与关键决策

记录日期：2026-10-26　依据：`路线工具_开发任务书_v1.md`（v1，436 行）

## 1. 需求理解（复述给未来的自己）

做一台“离线跑圈机”：用户在地图上点出操场/校园一圈的闭合路线，给出速度（km/h）与圈数，
App 用**系统模拟位置**接口把坐标按 500 ms 的节奏写进系统，让第三方运动 App 记录到一条匀速跑圈的轨迹。

明确**不做**的事：

- 不预置任何真实地点坐标；任务书没确认 B 操场坐标，就不许把地图中心或“大概位置”当 B 操场。
- 不修改、不注入、不 hook 第三方应用（VirtGO 等），不替用户“刷成绩”。
- 不做账号、云同步、服务器、上传轨迹。
- 不承诺第三方 App 一定采信模拟位置——这是系统与对方的决定。

## 2. 数值与格式约定（实现严格照此执行）

| 项 | 约定 | 实现位置 |
| --- | --- | --- |
| 坐标系 | WGS-84（字段 `latitude` / `longitude`，先纬后经） | `RouteDefinition`、`RouteJsonCodec` |
| GeoJSON 顺序 | 仅导出/展示时才用 `[lon, lat]` | — |
| 校验 | 纬度 [-90, 90]、经度 [-180, 180]，拒绝 NaN / Infinity | `GeoPoint` |
| 速度 | 0.5–60 km/h，默认 9；`mps = kmh / 3.6` | `RunConfig` |
| 圈数 | 1–1000 的整数，默认 5 | `RunConfig` |
| tick | 默认 500 ms（100–5000 可调） | `RunConfig` |
| 节点上限 | 5000 | `RouteCompiler.MAX_POINTS` |
| 有效路线 | 去重后 ≥ 2 点、单圈 ≥ 1 米 | `RouteCompiler` |
| 少于 2 点 | 允许当草稿保存，禁止开始运行 | `RouteJsonCodec` 允许，`RouteCompiler` 拦截 |

## 3. 需要拍板的几件事（及我的选择）

### 3.1 “闭合”怎么算

**决策：路线永远闭合，最后一点自动连回第一点；单圈长度包含这条闭合边。**

理由：任务书要求“始终闭合”；如果允许开放路线，圈数、终点、累计距离都要额外定义，收益很低。
若用户把终点又点回起点（坐标与起点几乎重合），编译时去掉这个重复终点，避免多算一条~0 米的边。
去重阈值 0.01 米（`RouteCompiler.DUPLICATE_TOLERANCE_METERS`）。

### 3.2 进度用什么表达

**决策：只用“累计距离”一个变量，圈数由 `totalDistance % lapLength` 推导。**

- 距离 = `speedMps × 有效运行时间`（暂停期间不累计）。
- 已完成圈数 = `floor(distance / lapLength)`，且不超过目标圈数。
- 到达目标距离（容差 1e-6 米）时：距离精确等于目标、位置精确回到起点、圈数等于目标、状态置 COMPLETED。
- 位置由 `CompiledRoute.pointAt(distance % lapLength)` 二分查找段 + 球面插值（slerp）得到，跨 ±180° 正确。

好处：没有“圈数计时器 / 距离计时器”两个真相来源，卡顿、掉帧、暂停恢复都不会让两者互相打脸（T10、T11）。

### 3.3 时间用哪个钟

**决策：`SystemClock.elapsedRealtimeNanos()`，并由 `ActiveElapsedClock` 只累计“跑动中”的时间。**

不用 `System.currentTimeMillis()`：用户改系统时间会毁掉进度；不用 `uptimeMillis()`：深睡会停走。
`elapsedRealtime` 包含深睡，配合前台服务 + WakeLock，锁屏也能继续。

### 3.4 暂停时提交什么

**决策：暂停时仍然每 500 ms 提交一次，但速度写 0，位置保持暂停那一刻的位置。**

任务书要求“暂停期间以 0 速度定期提交同一位置”：
既让第三方 App 看到“停住了”，也避免某些实现把“很久没有新位置”当成 GPS 丢失。

### 3.5 模拟位置提交给哪些 provider

**决策：GPS 必须成功；NETWORK、FUSED 若系统支持就一并提交，不支持则跳过并逐项记录。**

理由：不同第三方 App 订阅的 provider 不同；能多喂一个就多一分成功率。但**不能**因为 NETWORK/FUSED
不可用就判定失败——很多 ROM 只允许 GPS 测试 provider。GPS 创建失败 → `PROVIDER_SETUP_FAILED`；
`SecurityException`（未选为模拟位置应用）→ `MOCK_APP_NOT_SELECTED`。失败时回滚已创建的所有 provider。

### 3.6 存储格式

**决策：一条路线一个 JSON 文件，文件名 = 路线 ID（`route-yyyyMMdd-HHmmss-xxxxxx`），目录 `files/routes/`。**

- 写入：`<id>.json.tmp` → `fsync` → 原子 `move` 覆盖，中途断电最多留一个 `.tmp`。
- 读取：解析失败的文件搬到 `corrupt/`（保留原文件名），**绝不静默删除或覆盖**，同时产生一条界面可见的警告。
- 不用数据库：路线数量是个位数到几十条，JSON 肉眼可读、可手工修复、可用 adb 备份。

### 3.7 状态机

`IDLE → READY → STARTING → RUNNING ⇄ PAUSED`，`RUNNING → COMPLETED`，
`STARTING/RUNNING/PAUSED → STOPPED | ERROR`，`COMPLETED/STOPPED/ERROR → READY`。

两条容易踩的补充规则：

1. **只有 provider 创建成功且首次提交成功，才允许 STARTING → RUNNING。**
2. **`stop()` 在非运行状态是空操作**（不抛异常、不改变状态）：重复点“停止”不会把已完成的任务改写成“已停止”，
   也不会产生第二个任务；`resume()` 只允许从 PAUSED 调用，其他地方用属于调用方 bug，显式抛异常。

## 4. 与任务书的偏差（如实记录）

| 项 | 任务书 | 实现 | 原因 |
| --- | --- | --- | --- |
| 签名 | “构建签名交付” | 生成本地自签名 keystore（`keystore/`，已忽略入库），release APK 用其签名 | 没有官方证书；本地自签名足以安装与升级验证，私钥不外传 |
| 界面语言 | 中文 | 只有中文文案 | 单人本地使用 |
| 地图瓦片 | OSM | 直连 `tile.openstreetmap.org`，样式 JSON 内署名 | 无网络密钥；正式长期使用应换自建瓦片 |
| 示例路线 | 不预置 B 操场 | `samples/` 用 `(0,0)` 附近合成坐标 | 任务书明确禁止猜坐标 |

## 5. 未决 / 待用户确认

- B 操场的真实坐标（以及是否要把它做成一条内置示例）——**需要用户在真机上点选或提供经纬度**。
- 是否需要在正式版里换掉公共 OSM 瓦片。
- 是否需要导出轨迹（GPX/GeoJSON）——当前在 P1 之外，未实现。

## 6. 0.1.1 新增决策（真机反馈后，2026-10-26 晚）

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 闭合是否可选 | 菜单「闭合路线」可切换；`closed=false` 表示跑完单程后**原路返回** | 用户明确要求「最后一个点是否和第一个点合并由自己选」；不闭合也必须能跑，往返是最自然的计圈方式 |
| 不闭合怎么算一圈 | 一圈 = 单程的两倍；`RouteCompiler` 把点序列展开成 `p0…pn-1, pn-2…p1`，末段仍由既有闭合边回到起点 | 复用同一套「距离→位置」数学，不为往返写第二套插值逻辑 |
| 单点位置 | 新增 `RunRequest` 单点模式（无路线、速度 0、圈数 1），服务每个 tick 提交同一个坐标直到停止 | 用户要「直接传送单点位置」；把位置钉在一点比画一条 1 米路线更直观 |
| 地图全黑怎么兜底 | 内置三种栅格瓦片源（OSM 官方 / OSM France / OSM Germany），菜单可切换；10 秒看门狗把原因写到地图底部；地图区域先铺浅灰底 | 真机上完全看不到地图，无法判断是网络、样式还是渲染问题；有可见原因与备选源才能自助排查 |
| 模拟位置应用列表为空 | 清单声明 `android.permission.ACCESS_MOCK_LOCATION` | AOSP Settings 的 `AppPicker` 用该权限过滤候选应用，未声明就不会出现在列表里（已核对 AOSP 源码） |
| 版本号 | 0.1.1 / versionCode 2（0.1.2 起为 3） | 覆盖安装可保留已保存路线（T24） |

> 未因此改动的地方：不预置任何真实地点坐标；不修改第三方应用；闭合/不闭合都以「累计距离」为唯一进度来源。

## 7. 0.1.2 追加决策（第二轮真机反馈）

| # | 决策 | 理由 / 取舍 |
| --- | --- | --- |
| 1 | 传送 = 「传送选点」模式和单点模式共用一条链路（`RunRequest.createSinglePoint` + 前台服务钉住） | 传送语义就是「把位置搬到某点」，不需要新引擎；复用同一套 tick/通知/WakeLock/错误处理，少一份会腐化的代码 |
| 2 | 传送选点模式放在 ViewModel（`RouteEditorViewModel.teleportMode`） | 选点期间旋转屏幕会重建 Activity，模式状态放 ViewModel 才不会丢；已有 `pendingSinglePoint` 的同款教训 |
| 3 | 运行中不允许传送，先要求停止 | 一个 runId 一个任务；不允许两个入口同时改同一份模拟位置，避免停止/启动交错出现「僵尸 provider」 |
| 4 | 新增高德瓦片，坐标换算放 `route-core/ChinaShift` | 高德底图是 GCJ-02，路线是 WGS-84；换算必须双向（画路线要正向、点地图要逆向），放进核心模块才能被 JVM 单测覆盖 |
| 5 | 逆变换用不动点迭代 5 次，而不是查表 | 公式公开、无外部数据依赖；迭代 5 次往返误差 < 0.5 米（单测断言），足够画底图与点选 |
| 6 | 百度不接入 | 百度瓦片是 BD-09 私有矢量接口，需要官方 SDK 与 key；本应用不接第三方 SDK、不申请 key，宁可少一个源也不偷偷用私有接口 |
| 7 | 「虚拟定位到底生效没有」用系统回读做判定（`LocationVerifier`），不靠“调用没报错” | 提交成功只说明 API 没抛异常；只有 `getLastKnownLocation` 读回同一坐标才算系统收下。判定逻辑放 simulation-core，可单测 |
| 8 | 自检只读 `getLastKnownLocation`，不长期监听 | 监听会额外耗电，也会让用户以为应用在偷偷定位；每 3 秒读缓存在诊断页足够说明问题 |

## 8. 0.1.3 追加决策

| 问题 | 决策 | 理由 |
| --- | --- | --- |
| 为什么默认底图改成高德 | `TILE_SOURCES` 第一项改为 `amap` | 国内网络与模拟器里 `tile.openstreetmap.org` 解析到黑洞地址并 `SSLHandshakeException`，OSM 默认值等于「一打开就是空白」；高德 `style=7` 实测 200 且中文路名完整 |
| 高德坐标系不一致怎么办 | 显示层换算：`ChinaShift.wgs84ToGcj02` / `gcj02ToWgs84`，存储与计算始终 WGS-84 | 任务书要求数据是 WGS-84；换算只发生在「画出来」和「点地图取坐标」这一层，避免污染路线数据 |
| 瓦片打不开时界面怎么表现 | 样式 10 秒看门狗 + 启动时对当前源做一次 4 秒 HEAD 探测，两者都作用在地图区的 `mapStatus` 文案 | 用户看到空白时最需要的是原因和下一步动作，不是日志；但探测不能阻塞界面，也不影响路线与引擎 |
| 加完节点看不到点 | 首个节点自动放大到 16 级；后续节点若不在视野内则重新取景 | 「点了没反应」是地图类工具最常见的误解来源；用 `isVisible` 做条件，避免每次加点都拉视野打断用户 |
| GPX 用什么结构 | 只读写 `trk/trkseg/trkpt` 单段折线，导出带 `<name>` | 这是运动手表与各类轨迹工具的公共子集；不支持 `wpt`/`rte` 是有意为之（本工具只关心一条连好的路线） |
| 不闭合路线怎么导出 | 按「原路返回」展开后的点序列导出 | GPX 没有「闭合」概念；展开后导入到别处仍是一条可跑完整来回的轨迹，几何信息不丢 |
| 模拟器实测是否改变「未实测」口径 | 模拟器结论单独成节，不替代真机 | AOSP 行为与厂商 ROM 不同；`delivery` 里真机项仍标「未实测」，模拟器项标「已在模拟器验证」 |
| 为什么只给 debug 包加 x86_64 | `abiFilters` 只在 debug 追加 `x86_64` | release 面向真机，多一个 ABI 只会让包变大；调试包要能在 x86_64 模拟器上装 |
