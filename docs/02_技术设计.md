# 02 技术设计

## 1. 模块划分

| 模块 | 类型 | 依赖 | 职责 |
| --- | --- | --- | --- |
| `:route-core` | 纯 Java（java-library） | 无 | 地理计算、路线编译、进度引擎、有效计时、状态机、错误码 |
| `:simulation-core` | 纯 Java（java-library） | 无 | “创建/启用/提交/移除测试 provider”的可注入会话逻辑 |
| `:app` | Android 应用 | 上面两个 | 界面、地图、前台服务、持久化、设置检查、诊断 |
| `:location-probe` | Android 应用（独立包名） | 无 | 独立读取系统位置，作为“坐标真的进系统了”的旁证 |

把“能不能被单测”和“必须连真机”拆开：前两个模块不 import 任何 `android.*`，
所以 95 个 JVM 单元测试可以完全脱离手机运行；app 里剩下的只有装配与 UI。

## 2. 关键类

### route-core

- `GeoPoint`：不可变经纬度，构造即校验范围与 NaN/Infinity。
- `GeoMath`：Haversine 距离（`R = 6371008.8`）、初始方位角、球面线性插值、经度归一化。
- `RouteCompiler`：输入点列 → `CompiledRoute`。去连续重合点、去“又点回起点”的重复终点、
  要求 ≥2 点且单圈 ≥1 米，输出顶点数组、每段长度、前缀距离、单圈长度（含闭合边）。
- `CompiledRoute`：`pointAt(alongMeters)` 用前缀距离二分 + 段内 slerp；`bearingAt` 同理。
- `RouteEngine`：`progressAt(route, config, elapsedNanos)` → `Progress`（位置/方位/距离/圈数/是否完成）。
- `ActiveElapsedClock`：只累计“跑动中”的时间，暂停不计时；`formatDuration` 输出 `HH:MM:SS` / `MM:SS`。
- `LoopStateMachine`：显式迁移表 + 幂等 `stop()`（非运行态为空操作，不把 COMPLETED 改写成 STOPPED）。
- `TickGapPolicy`：T11 的策略 — `defaults()` = 5 秒上限，`shouldPause(last, now)` 判「实际间隔严格大于上限」，`reasonForGap` 生成给用户看的原因（自动暂停 + 从暂停点恢复）。抽成纯逻辑是为了能在 JVM 上覆盖边界。
- `RunConfig` / `RunState` / `RunErrorCode` / `InvalidRouteException`。

### simulation-core

- `MockProviderApi`：5 个方法（支持性查询、add、enable、提交位置、remove），Android 侧由
  `AndroidMockProviderApi` 实现，测试侧用内存假实现。
- `MockLocationSession`：按 gps → network → fused 顺序创建并启用测试 provider；
  GPS 必须存在，其余不支持则跳过；任一 add/enable 失败则**回滚已创建的全部 provider**；
  `publish(MockFix)` 向所有已创建 provider 提交同一个完整 `Location`；`stop()` 逆序只移除**本次创建**的。
- `MockFix`：一次提交所需的全部字段（经纬度、精度、速度、方位、时间戳、`elapsedRealtimeNanos`）。

### app

| 包 | 类 | 说明 |
| --- | --- | --- |
| `model` | `RouteDefinition` / `RouteJsonCodec` / `RouteSummary` | 路线数据与文件格式 |
| `storage` | `RouteRepository` | 原子写入、排序列举、损坏隔离、删除 |
| `run` | `RunSnapshot` / `SimulationStateRepo` / `RunRequest` / `PendingRunRegistry` | 跨组件状态与启动请求传递（避免 Intent 体积上限） |
| `simulation` | `AndroidMockProviderApi` | `LocationManager` 适配层 |
| `service` | `SimulationService` | 前台服务：tick 调度、WakeLock、通知、状态机宿主、清理 |
| `ui` | `MainActivity` / `RouteEditorViewModel` / `SettingsCheckActivity` / `DiagnosticsActivity` | 界面 |
| `map` | `RouteMapController` | MapLibre 封装：样式、图层、手势、跟随 |
| `settings` | `SettingsInspector` | 设置项检查与修复指引 |
| `diagnostics` | `DiagnosticLog` | 环形日志、坐标日志开关 |

## 3. 运行数据流

```
MainActivity ──(RunRequest)──▶ PendingRunRegistry ──(runId)──▶ SimulationService
      ▲                                                            │
      │ LiveData<RunSnapshot>                                      │ 每 500ms
      └────────────── SimulationStateRepo ◀── publish(snapshot) ───┤
                                                                   ├─▶ ActiveElapsedClock
                                                                   ├─▶ RouteEngine.progressAt
                                                                   └─▶ MockLocationSession.publish
```

- 界面**只**订阅 `SimulationStateRepo`，不持有服务引用；旋转屏幕只重新订阅（任务书要求）。
- 服务启动时从 `PendingRunRegistry` 取出请求（进程内），因此大路线（5000 点）不会被塞进 Intent。
- 每次 tick 用同一个 `runId` 与固定的 `route/config` 计算，重复点“开始”时若已有活跃 run，直接忽略。

## 4. 线程模型

| 线程 | 干什么 |
| --- | --- |
| 主线程 | UI、通知更新、地图 |
| `HandlerThread("simulation-tick")` | 每 `tickIntervalMs` 计算进度并调用 `setTestProviderLocation` |
| Gradle/测试 | 无 Android 依赖，纯 JVM |

`MockLocationSession` 与 `ActiveElapsedClock` 只在 tick 线程访问；`SimulationStateRepo.publish` 内部
`postValue` 切回主线程。停止时先 `quitSafely()` 再释放 WakeLock，避免 tick 打到已释放资源上。

## 5. 前台服务与资源

- `android:foregroundServiceType="location"`；`startForeground` 必须在上传位置前完成（Android 10+ 限制）。
- 通知：低优先级常驻通知，含状态行 + 「暂停/继续」+「停止」两个 `PendingIntent`。
- `PARTIAL_WAKE_LOCK`（tag `RouteWorkshop:Simulation`）带超时并在 tick 中续期，`cleanup()` 里释放。
- `START_NOT_STICKY`：不允许系统用“过期参数”把任务复活；`onTaskRemoved` 主动停止并清理。
- `cleanup()` 幂等：停 tick → 停 session → 释放 WakeLock → 停前台 → 状态回 STOPPED 并落盘错误（若有）。
- 权限被撤回、系统定位被关闭：下一次 tick 检测到就 `fail(...)` 并停止，不留后台僵尸。

## 6. 错误码与用户可见文案

| 码 | 触发点 | 界面表现 |
| --- | --- | --- |
| `ROUTE_INVALID` | 点数不足、单圈 < 1 米、坐标非法 | 提示后停在 READY |
| `LOCATION_PERMISSION_MISSING` | 未授予定位权限 | 引导去设置 |
| `MOCK_APP_NOT_SELECTED` | `addTestProvider` 抛 `SecurityException` | 引导“开发者选项 → 模拟位置信息应用” |
| `LOCATION_DISABLED` | 系统定位总开关关闭 | 引导打开定位 |
| `PROVIDER_SETUP_FAILED` | GPS 测试 provider 创建失败（非权限原因） | 提示 provider 不支持 |
| `PUBLISH_FAILED` | `setTestProviderLocation` 抛异常 | 提示提交失败并停止 |
| `SCHEDULER_INTERRUPTED` | tick 被意外中断/线程异常 | 提示调度中断 |

## 7. 地图

- MapLibre Android SDK 13.7.1，样式为内联 JSON（栅格瓦片 `https://tile.openstreetmap.org/{z}/{x}/{y}.png`，
  `attribution` 字段带 OSM 署名）。
- 三个 `GeoJsonSource`：`route-line`（LineLayer）、`route-vertices`（CircleLayer）、`run-position`。
- `OnMapClickListener` 负责加点；拖动/缩放由 MapLibre 自己消费，不会触发 click（任务书要求的“区分”）。
- 用户一旦手动平移/缩放，自动跟随关闭（避免“地图自己跑”的违和感），可点按钮恢复跟随。

## 8. 测试策略

| 层次 | 手段 | 覆盖 |
| --- | --- | --- |
| 纯逻辑 | JUnit4（95 个用例） | 几何、编译、进度、状态机、调度间隔策略、编解码、仓库、会话回滚与残留清理 |
| 手工 | 真机清单 T01–T24 | 模拟位置是否真的进系统、锁屏、杀进程、升级覆盖 |
| 旁证 | 定位探针 | 独立包名读取系统位置，确认坐标在动且被标记为 mock |

JVM 单测**不能**证明“系统收到了坐标”，这一步只能在真机上做，报告里必须如实标注是否实测。

## 6. 0.1.1 增量设计

### 6.1 不闭合路线（原路返回）

- `CompiledRoute` 新增 `closed`、`pathPointCount`：前者表示用户是否选了闭合，后者是用户实际点的节点数（不含回程折返点）。
- `RouteCompiler.compile(List<GeoPoint> points, boolean closed)`：闭合时行为不变；不闭合时 `buildOutAndBackRing` 生成
  `p0…pn-1, pn-2…p1` 的轨迹，`CompiledRoute` 的末段仍是「最后一点 → 第一点」的闭合边，于是整圈长度 = 2 × 单程。
- `RouteDefinition.closed` 参与 JSON 持久化（键 `closed`），旧文件缺该键时按 `true` 处理，保证向后兼容。

### 6.2 单点位置模式

- `RunRequest` 有两种形态：带 `CompiledRoute` 的路线模式、只带 `GeoPoint` 的单点模式（`isSinglePoint()`）。
- `RunSnapshot.singlePoint` 让界面把「圈数」列显示成「单点」，把状态提示换成「单点位置发送中（速度 0）」。
- `SimulationService.startSinglePointRun()`：与路线模式共用 tick、通知、WakeLock、错误处理，只是每 tick 用固定坐标、速度 0、`bearing` 取 0。

### 6.3 地图可诊断

- `RouteMapController.TileSource`：`label()`、`urlTemplate()`、`attribution()`；内置三种源，选择写入 SharedPreferences（下次启动沿用）。
- 样式 JSON 先画 `background`（浅灰），再画路线/点位图层；瓦片加载失败时地图区域不是纯黑。
- `STYLE_TIMEOUT_MS = 10_000` 看门狗：超时或样式错误通过 `StatusListener` 把文案交给界面，显示在底部的 `mapStatus` 条上。
- 菜单「地图瓦片源」列出三种源并标出当前项；切换立即重建样式。

### 6.4 模拟位置应用列表

- 清单声明 `ACCESS_MOCK_LOCATION`（`tools:ignore="MockLocation"` 并附注释说明原因）。
- 开始运行前仍会 `probeMockProvider()` 实测一次「能不能 addTestProvider」，据此区分「未选为模拟位置应用」「provider 不可用」等原因。

### 6.5 测试

- 0.1.1 共 **107** 个 JVM 用例：route-core 56（GeoMath 9、RouteCompiler 17、RouteEngine 13、LoopStateMachine 7、TickGapPolicy 10）、
  simulation-core 16、app 35（RouteJsonCodec 9、RouteRepository 10、RouteEditorViewModel 12、RunRequest 4）。
- 新增覆盖：不闭合路线的圈长/折返点/过短拒绝、`closed=false` 往返编解码、ViewModel 闭合切换与载入、单点请求的构造与状态。

## 7. 0.1.2 新增结构

### 7.1 传送（Teleport）

- 入口：`MainActivity.onMenuItemClick` → `action_teleport` → `toggleTeleportMode()`。
- 状态：`RouteEditorViewModel.teleportMode`（放 ViewModel，旋转不丢）。
- 地图点击：`RouteMapController.attach` 的回调里先判 `viewModel.isTeleportMode()`，命中就 `teleportTo(point)`，否则按原来的「加节点」处理。
- 执行：`teleportTo` → `requestPermissionsThenSendPoint(point)` → `beginSinglePoint(point)` → `SimulationService.start(this, RunRequest.createSinglePoint(point))`；与「发送单点位置」完全同一条链路（速度 0、坐标钉住、通知可控）。
- 约束：运行中（`snapshot.isActive()`）拒绝传送并提示先停止。

### 7.2 高德底图与坐标换算

- `route-core/ChinaShift`：`outOfChina`、`wgs84ToGcj02`、`gcj02ToWgs84`（5 次不动点迭代）。
- `RouteMapController.TileSource` 增加 `CoordSystem`（`WGS84` / `GCJ02`）与多子域 `tileUrls`；`TILE_SOURCES` 现有 4 项：OSM 官方（默认）、高德（GCJ-02）、OSM France、OSM Germany。
- 所有出图/入图都过两道转换：`toDisplay(GeoPoint)`、`fromDisplay(lat, lon)`，覆盖 `renderRoute`、`renderRunner`、`fitRoute`、`followRunner`、`cameraCenter` 与地图点击。
- 切换瓦片源会重建样式并重绘 `currentPoints`，无需用户重新点选。

### 7.3 位置自检

- `simulation-core/LocationVerifier`：纯逻辑判定 `ACCEPTED / MISMATCH / NOT_RECEIVED / NOT_MARKED_MOCK / NO_EXPECTED`，默认容差 20 米；`explain(...)` 给出「该怀疑谁」的说明。
- `app/diagnostics/SystemLocationReader`：读 `gps / network / fused` 的 `getLastKnownLocation`，返回 provider 是否可用、位置、`isMock`、距今毫秒；无定位权限时返回空列表而不是抛异常。
- `DiagnosticsActivity` 顶部黄色区块 `textSelfCheck`：`onResume` 起每 3 秒刷新，`onPause` 停止；展示「应用最后提交」+ 每个 provider 的「系统读回」与结论。
- 局限：`fused` 由 Google Play 服务注册，`addTestProvider("fused")` 多数机型会抛 `IllegalArgumentException`，因此 `fused` 常常显示「本机没有这个 provider」或读不到位置——这不是本应用没提交，而是该 provider 不接受测试位置，文档中已写明。

## 8. 0.1.3 新增结构

### 8.1 GPX 读写（`route-core`）

`org.localroute.core.GpxCodec`：

- `String encode(String routeName, List<GeoPoint> points)`：输出 `gpx(1.1) / trk / name / trkseg / trkpt[lat,lon]`，
  坐标固定 6 位小数（约 0.1 米），不写 elevation/time（本工具没有这些数据，写空标签反而误导）。
- `List<GeoPoint> decode(String xml)`：只认 `trkpt`，按文档顺序收集；遇到没有 `lat`/`lon`、
  非数字、越界的点抛 `GpxFormatException`；不支持 `wpt`/`rte`（有意省略，见 `docs/01_需求与决策.md` 第 8 节）。
- 解析用 `javax.xml.parsers.DocumentBuilderFactory`，开启 `disallow-doctype-decl` 与
  `external-general-entities=false`，避免 XXE（导入的是外部文件，必须当成不可信输入）。

界面侧：`MainActivity` 用 `ActivityResultContracts.CreateDocument("application/gpx+xml")` 导出、
`OpenDocument` 导入；导出前要求至少 2 个节点，导入后走 `viewModel.replacePoints(...)` 并 `refreshDraft(true)`。

### 8.2 瓦片探测与地图状态

- `RouteMapController.probeTiles()`：对当前源的第一个 URL 发起 HEAD 请求，
  连接/读取超时各 4 秒，`User-Agent` 带应用名与版本；2xx 视为可达，其余（含异常）把原因写进 `mapStatus`。
- `selectTileSource(int)`：切换时重建样式并重新探测；`TILE_SOURCES` 的元素带 `CoordSystem`，
  `toDisplay` / `fromDisplay` 按当前源决定是否走 `ChinaShift`。
- 样式 10 秒未就绪的看门狗仍在：探测管「能不能取到瓦片」，看门狗管「地图引擎有没有起来」，两者互补。

### 8.3 取景（`fitRoute` / `isVisible`）

- 单点：`animateCamera(newLatLngZoom(toDisplay(p), 16f))`；两点及以上：`newLatLngBounds(..., 96)`，
  失败（极端重合）时退化为居中。
- `isVisible(point)` 用 `getProjection().getVisibleRegion().latLngBounds.contains(...)`；
  地图未就绪时返回 `false`，让调用方重新取景，而不是静默忽略。

### 8.4 调试包 ABI

`app/build.gradle` 的 release 保持 `arm64-v8a` / `armeabi-v7a`；debug 追加 `x86_64`，
用于在 x86_64 模拟器上安装调试包（MapLibre 自带该 ABI 的 `.so`）。
