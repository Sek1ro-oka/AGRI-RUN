# 02 技术设计

## 1. 模块划分

| 模块 | 类型 | 依赖 | 职责 |
| --- | --- | --- | --- |
| `:route-core` | 纯 Java（java-library） | 无 | 地理计算、路线编译、进度引擎、有效计时、状态机、错误码 |
| `:simulation-core` | 纯 Java（java-library） | 无 | “创建/启用/提交/移除测试 provider”的可注入会话逻辑 |
| `:app` | Android 应用 | 上面两个 | 界面、地图、前台服务、持久化、设置检查、诊断 |
| `:location-probe` | Android 应用（独立包名） | 无 | 独立读取系统位置，作为“坐标真的进系统了”的旁证 |

把“能不能被单测”和“必须连真机”拆开：前两个模块不 import 任何 `android.*`，
所以 95 个 JVM 单元测试可以完全脱离手机运行；app 里剩下的只有装配与 UI。

## 2. 关键类

### route-core

- `GeoPoint`：不可变经纬度，构造即校验范围与 NaN/Infinity。
- `GeoMath`：Haversine 距离（`R = 6371008.8`）、初始方位角、球面线性插值、经度归一化。
- `RouteCompiler`：输入点列 → `CompiledRoute`。去连续重合点、去“又点回起点”的重复终点、
  要求 ≥2 点且单圈 ≥1 米，输出顶点数组、每段长度、前缀距离、单圈长度（含闭合边）。
- `CompiledRoute`：`pointAt(alongMeters)` 用前缀距离二分 + 段内 slerp；`bearingAt` 同理。
- `RouteEngine`：`progressAt(route, config, elapsedNanos)` → `Progress`（位置/方位/距离/圈数/是否完成）。
- `ActiveElapsedClock`：只累计“跑动中”的时间，暂停不计时；`formatDuration` 输出 `HH:MM:SS` / `MM:SS`。
- `LoopStateMachine`：显式迁移表 + 幂等 `stop()`（非运行态为空操作，不把 COMPLETED 改写成 STOPPED）。
- `TickGapPolicy`：T11 的策略 — `defaults()` = 5 秒上限，`shouldPause(last, now)` 判「实际间隔严格大于上限」，`reasonForGap` 生成给用户看的原因（自动暂停 + 从暂停点恢复）。抽成纯逻辑是为了能在 JVM 上覆盖边界。
- `RunConfig` / `RunState` / `RunErrorCode` / `InvalidRouteException`。

### simulation-core

- `MockProviderApi`：5 个方法（支持性查询、add、enable、提交位置、remove），Android 侧由
  `AndroidMockProviderApi` 实现，测试侧用内存假实现。
- `MockLocationSession`：按 gps → network → fused 顺序创建并启用测试 provider；
  GPS 必须存在，其余不支持则跳过；任一 add/enable 失败则**回滚已创建的全部 provider**；
  `publish(MockFix)` 向所有已创建 provider 提交同一个完整 `Location`；`stop()` 逆序只移除**本次创建**的。
- `MockFix`：一次提交所需的全部字段（经纬度、精度、速度、方位、时间戳、`elapsedRealtimeNanos`）。

### app

| 包 | 类 | 说明 |
| --- | --- | --- |
| `model` | `RouteDefinition` / `RouteJsonCodec` / `RouteSummary` | 路线数据与文件格式 |
| `storage` | `RouteRepository` | 原子写入、排序列举、损坏隔离、删除 |
| `run` | `RunSnapshot` / `SimulationStateRepo` / `RunRequest` / `PendingRunRegistry` | 跨组件状态与启动请求传递（避免 Intent 体积上限） |
| `simulation` | `AndroidMockProviderApi` | `LocationManager` 适配层 |
| `service` | `SimulationService` | 前台服务：tick 调度、WakeLock、通知、状态机宿主、清理 |
| `ui` | `MainActivity` / `RouteEditorViewModel` / `SettingsCheckActivity` / `DiagnosticsActivity` | 界面 |
| `map` | `RouteMapController` | MapLibre 封装：样式、图层、手势、跟随 |
| `settings` | `SettingsInspector` | 设置项检查与修复指引 |
| `diagnostics` | `DiagnosticLog` | 环形日志、坐标日志开关 |

## 3. 运行数据流

```
MainActivity ──(RunRequest)──▶ PendingRunRegistry ──(runId)──▶ SimulationService
      ▲                                                            │
      │ LiveData<RunSnapshot>                                      │ 每 500ms
      └────────────── SimulationStateRepo ◀── publish(snapshot) ───┤
                                                                   ├─▶ ActiveElapsedClock
                                                                   ├─▶ RouteEngine.progressAt
                                                                   └─▶ MockLocationSession.publish
```

- 界面**只**订阅 `SimulationStateRepo`，不持有服务引用；旋转屏幕只重新订阅（任务书要求）。
- 服务启动时从 `PendingRunRegistry` 取出请求（进程内），因此大路线（5000 点）不会被塞进 Intent。
- 每次 tick 用同一个 `runId` 与固定的 `route/config` 计算，重复点“开始”时若已有活跃 run，直接忽略。

## 4. 线程模型

| 线程 | 干什么 |
| --- | --- |
| 主线程 | UI、通知更新、地图 |
| `HandlerThread("simulation-tick")` | 每 `tickIntervalMs` 计算进度并调用 `setTestProviderLocation` |
| Gradle/测试 | 无 Android 依赖，纯 JVM |

`MockLocationSession` 与 `ActiveElapsedClock` 只在 tick 线程访问；`SimulationStateRepo.publish` 内部
`postValue` 切回主线程。停止时先 `quitSafely()` 再释放 WakeLock，避免 tick 打到已释放资源上。

## 5. 前台服务与资源

- `android:foregroundServiceType="location"`；`startForeground` 必须在上传位置前完成（Android 10+ 限制）。
- 通知：低优先级常驻通知，含状态行 + 「暂停/继续」+「停止」两个 `PendingIntent`。
- `PARTIAL_WAKE_LOCK`（tag `RouteWorkshop:Simulation`）带超时并在 tick 中续期，`cleanup()` 里释放。
- `START_NOT_STICKY`：不允许系统用“过期参数”把任务复活；`onTaskRemoved` 主动停止并清理。
- `cleanup()` 幂等：停 tick → 停 session → 释放 WakeLock → 停前台 → 状态回 STOPPED 并落盘错误（若有）。
- 权限被撤回、系统定位被关闭：下一次 tick 检测到就 `fail(...)` 并停止，不留后台僵尸。

## 6. 错误码与用户可见文案

| 码 | 触发点 | 界面表现 |
| --- | --- | --- |
| `ROUTE_INVALID` | 点数不足、单圈 < 1 米、坐标非法 | 提示后停在 READY |
| `LOCATION_PERMISSION_MISSING` | 未授予定位权限 | 引导去设置 |
| `MOCK_APP_NOT_SELECTED` | `addTestProvider` 抛 `SecurityException` | 引导“开发者选项 → 模拟位置信息应用” |
| `LOCATION_DISABLED` | 系统定位总开关关闭 | 引导打开定位 |
| `PROVIDER_SETUP_FAILED` | GPS 测试 provider 创建失败（非权限原因） | 提示 provider 不支持 |
| `PUBLISH_FAILED` | `setTestProviderLocation` 抛异常 | 提示提交失败并停止 |
| `SCHEDULER_INTERRUPTED` | tick 被意外中断/线程异常 | 提示调度中断 |

## 7. 地图

- MapLibre Android SDK 13.7.1，样式为内联 JSON（栅格瓦片 `https://tile.openstreetmap.org/{z}/{x}/{y}.png`，
  `attribution` 字段带 OSM 署名）。
- 三个 `GeoJsonSource`：`route-line`（LineLayer）、`route-vertices`（CircleLayer）、`run-position`。
- `OnMapClickListener` 负责加点；拖动/缩放由 MapLibre 自己消费，不会触发 click（任务书要求的“区分”）。
- 用户一旦手动平移/缩放，自动跟随关闭（避免“地图自己跑”的违和感），可点按钮恢复跟随。

## 8. 测试策略

| 层次 | 手段 | 覆盖 |
| --- | --- | --- |
| 纯逻辑 | JUnit4（95 个用例） | 几何、编译、进度、状态机、调度间隔策略、编解码、仓库、会话回滚与残留清理 |
| 手工 | 真机清单 T01–T24 | 模拟位置是否真的进系统、锁屏、杀进程、升级覆盖 |
| 旁证 | 定位探针 | 独立包名读取系统位置，确认坐标在动且被标记为 mock |

JVM 单测**不能**证明“系统收到了坐标”，这一步只能在真机上做，报告里必须如实标注是否实测。
