# 模拟器实测记录（0.1.3）

## 为什么要做

0.1.0 / 0.1.1 / 0.1.2 的所有结论都建立在 JVM 单元测试上，凡是涉及
`LocationManager.addTestProvider`、前台服务、通知、系统定位服务的行为，一律只能写「未实测」。
用户明确要求「自行安装一个安卓模拟器测试」，于是本轮把这条链路真正跑起来，
并把可以自动化的部分固化成证据。

模拟器能证明的东西：**坐标有没有真的进入系统定位服务**。
模拟器不能证明的东西：**真机 ROM 是否放行**。两者不要混为一谈。

## 环境

| 项目 | 值 |
| --- | --- |
| 设备 | Android Emulator AVD，API 35（Android 15），x86_64，1080×2340 |
| 主应用 | `org.localroute.app.debug`，versionCode 4 / 0.1.3（调试包额外打 x86_64 ABI） |
| 探针 | `org.localroute.probe`，独立包名、独立清单 |
| 网络 | 主机经代理直连；模拟器内 OSM 域名解析到黑洞地址 10.112.4.179 |
| SDK 路径 | `E:\Android\Sdk`（platform-tools / emulator / system-images 均在 E 盘） |

## 复现步骤

1. `adb install -r app/build/outputs/apk/debug/app-debug.apk`
2. `adb shell am start -n org.localroute.app.debug/org.localroute.app.ui.MainActivity`
3. 打开模拟器「开发者选项 → 选择模拟位置信息应用 → 路线工坊」，然后回到应用；
   如果列表里没有它，先覆盖安装 0.1.1 及以上版本（0.1.0 的清单没有 `ACCESS_MOCK_LOCATION`）。
4. 画一条两点路线（或「手动输入」经纬度），开始运行。
5. 另开探针 `org.localroute.probe`，点「开始监听」，观察是否收到带「模拟位置」标记的帧。
6. 需要核对系统侧读数时：`adb shell dumpsys location | grep 'last location'`。

## 观察结果

| 检查点 | 结果 |
| --- | --- |
| 首次启动底图 | 默认高德，中文路名可见；清空数据后仍是高德（默认值已改在常量顺序里） |
| 运行 | 速度 9.0 km/h、单圈 1.02 km、累计 39.7 m、用时 00:15、0/5 圈，红点沿路线前进 |

## 本轮发现并修掉的问题

1. **OSM 底图在模拟器（以及国内常见网络）里就是打不开**：域名解析到 10.112.4.179，
   连上去 `SSLHandshakeException`。原默认源就是它，所以「一打开一片白/黑」不是渲染问题。
   处理：默认改高德；保留 OSM 三源可选；加瓦片探测（HEAD 请求 4 秒超时）与可见提示。
2. **首个节点加完不放大**：世界地图上看不出点加在哪，像「点了没反应」。
   处理：`fitRoute` 对单点直接放大到 16 级；后续节点落在视野外时重新取景（`isVisible`）。
3. **高德 `style=8` 返回纯白瓦片**：`style=7` 才有路网与注记。已在常量里固定 7。
4. **模拟器跑不了调试包**：调试包只打 `arm64-v8a` / `armeabi-v7a`。
   处理：仅 debug 增加 `x86_64`，release 保持两个 ARM ABI 不变。

## 仍然没有验证的

- 真机（真我 GT Neo5）上的同一套流程。ROM 可能要求重启或重新选择模拟位置应用。
- 锁屏/切后台 10 分钟、调度被系统冻结 5 秒以上的真实表现（自动暂停逻辑只有 JVM 用例）。
- 高德瓦片接口的稳定性与授权状态；它和 OSM 一样是「能用就用、失效可切」的外部依赖。
