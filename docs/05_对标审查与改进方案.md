## 3. 方案一：地图接入与“数据太老”

### 3.1 直接回答

**可以使用高德、腾讯或百度。现有 MapLibre 选型不意味着不能改用这些地图。** 原任务书选择少外部依赖，不是用户永久拒绝官方 SDK 的要求。

但要区分“把厂商瓦片 URL 填进 MapLibre”与“使用厂商支持的地图 SDK”。当前高德方案属于前者。正式改进建议先完成**高德 Android 官方地图 SDK**，提供普通和卫星地图、地点搜索，再保留 MapLibre 作为备选实现。腾讯、百度可使用同一业务接口后续接入，不建议首轮同时维护三个新 SDK。

选择高德作为首个实现，是基于当前已有高德坐标显示链路、改造集中度较低的工程判断，不表示它在用户目标操场一定比腾讯或百度更新。

### 3.2 先确认“旧”的原因

在诊断页显示应用版本、实际底图提供方、地图类型、缩放级别和错误状态，然后按以下顺序复核：

1. 核对手机安装包是否为 0.1.3；记录实际地图源。当前默认只在没有历史偏好时生效，旧安装保存的 `tile_source=osm` 不会自动变为高德。
2. 在同一地点、相近缩放级别对照官方地图：分别观察道路/建筑标签与卫星影像，区分矢量数据更新和影像拍摄时间。
3. 在正常缓存策略下刷新、重试，检查是否只是网络失败后显示空白或旧内容。不要把清缓存当作所有问题的固定解法。
4. 保存对照截图、时间、坐标来源、地图类型及版本。仍存在差异再判断是否为接入图层或服务端数据问题。

验收依据是指定地点的可读性、对齐和稳定性，不承诺卫星影像为实时拍摄。

### 3.3 建议的接口和改动范围

新增业务接口 `MapController`，它只接收/返回业务坐标，Activity 不直接依赖厂商类：

```java
interface MapController {
    void renderEditor(EditorMapState state);
    void renderRunner(GeoPoint wgs84Point);
    void fitRoute(List<GeoPoint> wgs84Points);
    void setMapType(MapType type);
    void setOnPointSelected(PointListener listener);
    void retry();
    // 生命周期入口按实际 SDK 需要提供。
}
```

新增 `AmapMapController`、`MapProviderFactory`、`PlaceSearchRepository`；现有实现改名为 `MapLibreMapController` 或作为适配器保留。`activity_main.xml` 中地图容器由工厂挂载，避免界面只能容纳 MapLibre 的具体 View。

具体任务：

- 在 `app/build.gradle` 和版本目录固定经空项目验证的 SDK 版本；核对 ABI、最小系统版本、包体积和原生库冲突。
- 配置本人开发者 Key。当前 debug/release 包名不同，签名也不同，必须分别核对注册信息；高德接入使用应用包名及签名 SHA-1。平台账号、配额和使用条件以申请时控制台为准，不承诺永远免费无限量。
- Key 由本地配置/构建变量注入；不把签名口令写入文档。Android 端 Key 会进入 APK，应使用平台支持的包名和签名限制，不能声称编译进去就不可提取。
- 按 SDK 文档完成隐私说明及初始化顺序；只为地图显示和需要的检索接入组件，不额外接入定位 SDK 来替代现有模拟位置输出。
- 首页显式展示“地图：高德 / 普通”并允许选择卫星地图。搜索结果标出地点名、地址、距离或区域，选择后可“添加路线节点”或“传送”。
- 鉴权或网络失败给出可重试原因，保留手动坐标输入和已保存路线。切换到备选地图必须同步更新来源和坐标转换。

### 3.4 坐标边界

内部存储、路线计算、GPX 和系统模拟位置仍统一为 **WGS-84**。地图适配器处理显示坐标转换，页面和服务不得猜坐标系。

- 高德使用 GCJ-02，不能把点击返回值直接当作 WGS-84 提交系统。[高德坐标说明](https://developer.amap.com/faq/advisory/others/39838)
- 百度地图默认 BD-09LL，也支持配置 GCJ-02；接入时必须明确配置，不能当作普通 XYZ 地址直接替换。[百度坐标转换文档](https://lbsyun.baidu.com/docs/android?title=androidsdk%2Fguide%2Ftool%2Fcoordinate)
- 现有 `ChinaShift` 是近似换算。往返单元测试只能证明算法自洽，不能证明与真实地物绝对对齐；高德也没有提供任意坐标转回 GPS 的官方接口。保留原始点击坐标、来源和转换方式用于排查，不能伪称官方双向转换。
- 在已知 WGS-84 参考点测试标记、搜索结果、点击、保存重载和探针读数。初始工程验收建议显示往返误差不超过 2 米，绝对地物对齐按参考数据精度另记；这个数是验收目标，不是当前已证明的精度。

接入依据：[高德获取 Key](https://developer.amap.com/api/android-sdk/guide/create-project/get-key)、[高德 SDK 下载与组件说明](https://developer.amap.com/api/android-sdk/download)、[腾讯获取 Key](https://lbs.qq.com/mobile/androidMapSDK/developerGuide/getKey)。

## 4. 方案二：悬浮窗快捷传送

### 4.1 应交付的操作

用户在主页面开启悬浮控制，切到其他应用后，仍能展开小面板，选择常用地点或打开悬浮小地图，点“传送”后立即更新保持位置。面板同时提供当前位置、运行状态、暂停/继续、停止，以及行走/跑步/骑行速度选择。

“点击悬浮按钮后只是打开主 Activity”只能算临时快捷入口，不能算完成本需求。第一轮不必加入方向摇杆；快捷传送和基本控制优先。

建议分为两步交付：

1. 可拖动折叠球 + 常用点列表 + 连续传送 + 停止，先打通服务命令与状态反馈。
2. 悬浮小地图 + 地点搜索 + 速度模式 + 暂停继续，达到用户要求的完整快捷操作。

### 4.2 组件设计

新增 `overlay/FloatingPanelController`、`overlay/OverlayPermissionCoordinator`、`command/SimulationCommand` 和常用地点仓库。悬浮 UI 由现有前台模拟服务的会话管理，不再创建第二个定位服务或第二套 tick。

具体约定：

- Manifest 声明 `SYSTEM_ALERT_WINDOW`，先调用 `Settings.canDrawOverlays()` 检查，在用户点击“开启悬浮窗”后进入系统授权页，返回后重新检查。权限拒绝仅影响悬浮功能。
- 使用 `WindowManager.LayoutParams.TYPE_APPLICATION_OVERLAY`；小球区域可拖动、贴边和折叠，不能用透明全屏遮罩吞掉其他应用触摸。
- 小地图、搜索输入要处理焦点与软键盘；关闭输入后恢复不抢焦点的窗口状态。
- 缓存面板位置并限制在可用屏幕范围内；旋转、刘海、系统导航区、显示尺寸变化后重新校正。
- 浮窗与页面观察同一份 `RunSnapshot`，统一走服务线程串行命令，不在浮窗里直接操作 mock provider。
- 隐藏面板和停止模拟是两个清楚的动作；隐藏后通知仍能停止。停止会话、撤销授权、服务销毁时移除所有窗口与地图资源。

Android 授权依据：[Settings.canDrawOverlays](https://developer.android.com/reference/android/provider/Settings#canDrawOverlays(android.content.Context))。当前 targetSdk=35，不能只凭悬浮权限就假设任何后台启动都允许；Android 15 对依赖悬浮权限例外启动前台服务增加了可见浮窗条件，位置服务还有自身的启动前置条件。优先让用户在可见 Activity 中创建会话，后台面板控制已启动的服务；冷启动受限时显示返回应用继续的入口。[Android 15 行为变更](https://developer.android.com/about/versions/15/behavior-changes-15#fgs-start-restrictions)

### 4.3 连续传送必须走服务命令

当前页面的 `snapshot.isActive()` 会拒绝所有运行中的传送，包括“已经保持在 A 点，现在想去 B 点”。应补 `SET_HOLD_POSITION` 命令：

| 当前状态 | 传送后的处理 |
| --- | --- |
| 未运行 | 走现有权限检查，启动保持位置会话 |
| 单点保持 A | 在同一服务线程更新为 B，立即提交新帧并继续保持，速度 0；不重复创建 provider |
| 路线运行/暂停 | 面板明确显示“结束当前路线并传送”；用户执行后在同一命令流程结束路线、转单点保持，旧 tick 不能把位置拉回 |
| 启动中/停止中/错误 | 根据状态拒绝或排队，返回可见结果，不能静默丢命令 |

命令带 `commandId`、必要时带 `expectedRunId`；服务验证经纬度和当前会话，执行成功后发布带结果的快照。只有位置提交成功才显示“已传送”。地图选点仍可预览目标，但预览不等于系统已收到。

不要实现为异步 `stop()` 后立刻 `start()`：当前服务的 `stopSelf()`、清理和启动请求有时序关系，这种拼接容易丢请求或产生旧帧。

常用地点使用 WGS-84 保存 `id/name/latitude/longitude`；浮窗与首页共用。第一版不必上账号、云同步或收藏分组。

## 5. 方案三：默认不闭合，在页面栏下方显式连接起点

### 5.1 推荐页面结构

用户要求是：先自由逐点画路线，再决定当前末点是否连接第一点。不要让用户在开始前选择“闭合画圈/不闭合画圈”的工具模式。

```text
路线工坊                         更多
路线节点  [撤销] [清空] [添加坐标]
□ 将当前末点连接到第一个点       单程：xxx 米
------------------------------------------------
                    地图
------------------------------------------------
行走   跑步   骑行              速度：9.0 km/h
到终点：停止 / 原路往返          次数：1
开始     暂停/继续     停止      开启悬浮窗
```

- 新路线 `closed=false`，开关默认不勾；每个点按顺序连接，不自动补末点到首点。
- 开关放在工具栏下方、地图上方，文案明确写“将当前末点连接到第一个点”。
- 少于 2 个不同节点不能闭合；勾选后增加一条可辨认的末点→首点边，再取消就移除。
- 勾选表示“当前末点连接首点”：继续添加节点后，闭合边更新为新末点→首点，不把首点重复插入 `points[]`。
- 更改开关后同步预览长度、持久化和启动快照。已有保存路线应尊重自己的 closed 值。
- 页面可继续编辑草稿，但运行路线使用启动时的不可变快照；运行中明确显示“编辑将用于下次运行”，避免地图草稿被误认作当前轨迹。

若后续要支持“任意中间节点连回第一个点后再继续画分支”，需要图结构，已超出本次单条折线需求，不应在首轮过度设计。

### 5.2 不闭合不等于必须往返

用户明确了几何默认开口，但没有明确终点行为。本文建议新建开口路线默认“到终点停止”，并把“原路往返”作为单独运行选项；这是可调整的产品建议，不能假装已经得到用户确认。

建议增加 `EndBehavior`，使几何和运行策略独立：

| 几何 | EndBehavior | 行为及计数 |
| --- | --- | --- |
| 开口 | `STOP_AT_END`（建议默认） | A→B→C，停在 C；仅一次，显示单程长度 |
| 开口 | `SHUTTLE` | A→B→C→B→A 为一次往返；次数可设，不能显示成只走了单程 |
| 闭合 | `LOOP` | A→B→C→A 为一圈；圈数可设 |

首轮禁止开口路线“瞬移回起点然后继续”，避免引入用户没选的跳变。单点传送是独立保持模式，不通过速度设为 0 的路线绕过 `RunConfig` 校验。

### 5.3 算法与文件迁移

需要一起改 `RouteDefinition`、`RouteJsonCodec`、`RouteEditorViewModel`、`RouteCompiler`、`CompiledRoute`、`RunConfig`、`RouteEngine`、运行快照和页面，不能只把一个 `true` 改成 `false`。

具体设计：

1. `RouteDefinition.createNew()` 明确创建 `closed=false`；兼容旧构造器调用时逐处判断，不盲改所有默认参数。
2. 编译器保留原始几何；根据终点策略生成单程、往返或闭合的运行路径。单程 `pointAtDistance(d)` 必须 clamp 到末点，不能 `% lapLength` 后回起点。
3. `RouteEngine` 达到目标时根据策略选正确终点；单程终点是最后节点，闭合/完整往返终点是首点。完成帧速度设为 0；总距离不超目标。
4. 新存储格式建议 `schemaVersion=2`，几何保留 `points/closed`，另存 `runDefaults`，其中有 `endBehavior/repeatCount/speedMode/speedKmh`。运行时使用独立不可变 `RunConfig`。
5. v1 解码规则保持兼容：缺少 closed 的旧文件按原规则 true；v1 closed=false 原来是往返，迁移时保留该运行默认值。只有新建 v2 草稿采用新默认。迁移文件先备份，再原子写入，不能批量把旧路线改成开口单程。
6. 页面按策略显示“单程长度/往返长度/单圈长度”及“次数/圈数”。旧保存路线加载前后位置、距离和行为应一致。

建议 JSON 结构：

```json
{
  "schemaVersion": 2,
  "id": "example",
  "name": "示例开口路线",
  "coordinateSystem": "WGS84",
  "closed": false,
  "points": [
    { "latitude": 0.0, "longitude": 0.0 },
    { "latitude": 0.0, "longitude": 0.001 }
  ],
  "runDefaults": {
    "endBehavior": "STOP_AT_END",
    "repeatCount": 1,
    "speedMode": "RUN",
    "speedKmh": 9.0
  }
}
```

示例省略创建/更新时间，实际编码仍保留。坐标为合成测试点，不是用户操场。

## 6. 方案四：行走、跑步、骑单车速度预设

### 6.1 交互和默认值

保留现有 km/h 数字输入，增加三个可点击模式，模式速度允许分别修改并保存。建议初始值如下，属于本项目建议，不是引用 GoGoGo 默认值：

| 模式 | 建议初始值 | 行为 |
| --- | --- | --- |
| 行走 WALK | 5.0 km/h | 点击填入本人保存的行走速度 |
| 跑步 RUN | 9.0 km/h | 保留当前项目默认速度作为跑步初值 |
| 骑行 BIKE | 18.0 km/h | 点击填入本人保存的骑行速度 |

首次可保持跑步 9.0 km/h，减少升级意外；后续恢复上次模式。保持现有 0.5—60 km/h 范围及有限值校验。数字输入旁固定显示单位，不能依赖 hint 才知道是 km/h。

编辑数字时更新当前模式的已保存速度；要给出“已更新跑步预设”反馈，并提供恢复默认入口。`SpeedSettingsRepository` 保存三个值和当前模式，页面与浮窗共用同一状态，不能各持一份数字互相覆盖。

### 6.2 运行中变速的正确实现

当前引擎 `distance = speed × 全部有效时间` 适合整段定速。若运行 60 秒后把 9 km/h 改成 18 km/h，直接替换 config 会把前 60 秒也按新速度重算，距离从 150 米跳到 300 米。

需要改为分段累计：

```text
distance(now) = distanceAtSpeedChange
              + newSpeedMps × (activeElapsed(now) - elapsedAtSpeedChange)
```

收到 `SET_SPEED` 时，先用旧速度结算到命令执行时刻，再记录新的距离基点、有效时间基点与速度。所有变更在服务 Handler 中顺序执行。引擎可拆成“根据累计距离求路线位置”的纯函数，速度累计交给可测试的进度累加器。

- 暂停状态改速只改变待恢复速度，当前位置不动；继续后用新速度。
- 单点保持实际输出速度固定 0，三种模式只影响下次路线运行，面板应说明。
- 速度命令带当前 runId，防止迟到命令改到下一次任务；页面、浮窗、通知、快照显示同一个实际生效值。
- 如果第一轮仅完成启动前预设，运行中必须明确禁用改速；不能让用户看到新速度，却实际仍按旧速度运行。该阶段可以单独验收，但不能冒充完整的浮窗变速。

## 7. 关联代码缺陷的具体修复

### 7.1 地图状态恢复：R-005 / R-007

以不可变 `EditorMapState(points, closed, selectedIndex)` 保存编辑显示状态，单独保存最新 runner；调用者传入的 List 先复制，避免自己清空自己。

样式成功后统一 `restoreOverlays()`：

1. 检查当前样式代次，忽略旧回调；
2. 创建节点、路线、起点和 runner 的 source/layer；
3. 按缓存的 closed 值绘制；
4. 绘制最新 runner；
5. 保留合适相机位置，并重新按当前来源转换坐标。

起点使用独立单点源，或给节点加 index 属性并过滤 index=0。当前 `LAYER_START` 直接用全部顶点源、没有过滤，必须修正。

补回归：开口和闭合草稿分别切换高德→OSM→高德；点数、闭合边、起点颜色、runner、坐标及运行状态均保持正确。首轮地图异步加载前已有草稿也要覆盖。

### 7.2 地图可用状态：R-008

探测任务带 `styleGeneration/providerId`，切源和销毁时取消任务，返回主线程后检查代次与生命周期。观察当前视野的实际渲染/下载错误，区分鉴权、网络、超时和无数据；一次请求 0 级瓦片成功不能证明当前操场图层正确。

新增有意义的重试入口。当前同源选择直接返回“已经是当前瓦片源”，不是重新加载。请求使用可识别 UA 的设置要应用到实际地图请求链路，不能只设置诊断探测请求。缓存和署名按各提供方要求处理，不做批量预取。

### 7.3 异步保存：R-009

草稿加递增 `revision`，编辑、命名、闭合等变化均递增。发起保存记录 `(routeId, revision, definition)`，完成时仅当当前草稿仍是同一 ID、同一 revision 才 `markSaved()`。否则仅说明“已保存该版本；当前还有未保存改动”。

补可控延迟测试：开始保存后加点、改名、改变 closed，或者加载另一条路线；旧保存完成不能把新草稿标成干净。回调遵守 Activity 生命周期，不向已销毁页面更新 UI。

### 7.4 GPX 轨迹语义：R-010

默认按 `trk/trkseg` 选择轨迹段；没有轨迹时才支持 `rte` 路线。`wpt` 作为独立地点导入，不默认混入路线。多轨迹段应让用户选一段，或保留分段并明确提示，不能静默连起来。

容错解析可以保留，但需要导入预览，显示点数、来源类型、分段、跳过数量与异常长连线；用户确认替换前不覆盖现有草稿。保持外部实体/DTD 防护，损坏 XML 的恢复不能绕开分段限制。

补测试：远处航点+本地轨迹、两个相距很远的 trkseg、rte 与 trk 混合、注释里的伪标签、超上限截断。验收不能只验证“总共读到了几个点”。

### 7.5 文档与实际版本：R-011

- `docs/ISSUES.md` 中 I-105 仍写没有 GPX 导出，I-035 仍写 OSM 默认；应更新为历史记录或明确被哪个版本替代。
- `docs/THIRD_PARTY_NOTICES.md` 仍只列 OSM，需补实际高德来源及接入方式；“不缓存到磁盘”等描述要按 SDK 配置核实后再写。
- `docs/BUILD.md` 仍写 95 用例，应按本次实际 XML 汇总更新。
- 交付测试报告中 GPX 描述含“忽略 wpt/rte”“DOCTYPE 被禁用”等，与当前宽容解析实现不一致；应写实际行为，不沿用早期设计文案。
- 每次交付记录源码提交、APK 哈希、versionName/versionCode、包名、测试设备与地图来源，便于判断用户装的是哪一个版本。
