## 2. 新草稿语义（本轮最重要的行为变更）

| 场景 | 0.1.3 行为 | 0.2.0 行为 |
| --- | --- | --- |
| 新建路线 | 默认闭合 | 默认开口，复选框不勾 |
| 开口 + 跑到最后一个点 | 直接瞬移回起点继续（看起来像绕圈） | 默认停在终点并完成；只有选「原路往返」才沿原路回去 |
| 闭合 | 复选框在菜单里，绕圈 | 复选框固定在工具栏下方，勾上即绕圈 |
| 次数输入 | 始终可编辑 | 「到终点停止」时禁用并说明只跑一次 |
| 旧路线文件 | — | v1 按旧语义（往返）读取，运行结果不变 |

## 4. 本轮修掉的真实缺陷（都由模拟器或测试暴露）

1. **闭合 + 程序性恢复单选导致崩溃**：`RouteDefinition.withEndBehavior` 对 `closed && behavior != LOOP` 抛异常，界面同步控件时回调把它触发成 `IllegalArgumentException`，真机表现为闪退。修法：`MainActivity` 加 `syncingControls` 抑制回环、`RouteEditorViewModel.setEndBehavior` 在闭合时静默忽略，并补 `setEndBehaviorIsIgnoredWhileClosed` 回归用例。
2. **往返的「单程」显示成 1.5 倍**：`CompiledRoute.pathLengthMeters()` 直接取环长前缀，往返时给的是「去程 + 一段回程」。修法：编译期单独算 `oneWayLengthMeters`（往返取环长一半），并补 `pathLengthMeters_isAlwaysTheUsersOneWayPath`。
3. **多段 GPX 隐式连线**：DOM 解析把全部 `trkpt` 顺序拼起来。修法：只保留第一段 `trkseg`，其余段给出警告文本。

## 5. 明确没做的

- 真机（真我 GT Neo5）复验：本轮只有模拟器，锁屏/切应用/通知控制/强杀重开仍标「未实测」。
- 官方高德/百度 SDK：缺 Key 与鉴权，未接入；栅格瓦片非法定接口，随时可能失效。
- 常用点、悬浮地图/搜索、GPX 多段合并成多路线。
- 悬浮窗权限授予流程的自动化验证。
- `SimulationService` 仍没有 Robolectric/instrumentation 级测试，改速与传送只有单元层与手工验证。
