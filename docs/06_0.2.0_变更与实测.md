## 4. 本轮修掉的真实缺陷（都由模拟器或测试暴露）

1. **闭合 + 程序性恢复单选导致崩溃**：`RouteDefinition.withEndBehavior` 对 `closed && behavior != LOOP` 抛异常，界面同步控件时回调把它触发成 `IllegalArgumentException`，真机表现为闪退。修法：`MainActivity` 加 `syncingControls` 抑制回环、`RouteEditorViewModel.setEndBehavior` 在闭合时静默忽略，并补 `setEndBehaviorIsIgnoredWhileClosed` 回归用例。
2. **往返的「单程」显示成 1.5 倍**：`CompiledRoute.pathLengthMeters()` 直接取环长前缀，往返时给的是「去程 + 一段回程」。修法：编译期单独算 `oneWayLengthMeters`（往返取环长一半），并补 `pathLengthMeters_isAlwaysTheUsersOneWayPath`。
3. **多段 GPX 隐式连线**：DOM 解析把全部 `trkpt` 顺序拼起来。修法：只保留第一段 `trkseg`，其余段给出警告文本。

## 5. 明确没做的

- 真机（真我 GT Neo5）复验：本轮只有模拟器，锁屏/切应用/通知控制/强杀重开仍标「未实测」。
- 官方高德/百度 SDK：缺 Key 与鉴权，未接入；栅格瓦片非法定接口，随时可能失效。
- 常用点、悬浮地图/搜索、GPX 多段合并成多路线。
- 悬浮窗权限授予流程的自动化验证。
- `SimulationService` 仍没有 Robolectric/instrumentation 级测试，改速与传送只有单元层与手工验证。

## 6. 补充：可编辑配速与地图 Key 适配层（0.2.0 build 6）

### 6.1 三种可编辑配速（行走 / 跑步 / 骑行）

- 原来是四个写死的按钮（3/6/9/12 km/h），现在改成三个**具名预设**：默认行走 5.0、跑步 9.0、骑行 15.0 km/h。
- 单击 = 套用（没在跑时只填输入框；在跑时下发 `ACTION_SET_SPEED`，位置连续不跳变）。
- 长按 = 改数值：弹窗里填 km/h，校验 0.5—60 之外或非数字不保存；另有「恢复默认」。
- 值存在 `speed_presets` 偏好里，通过 `SpeedPresets.Store` 抽象读写，因此能在纯 JVM 里测（`SpeedPresetsTest` 8 例，含非法值回退、越界夹取、序号越界）。
- 手动输入框仍然保留，两者互不覆盖：预设只是帮你填数。

模拟器实测（API 35）：首屏按钮显示「行走 5.0 / 跑步 9.0 / 骑行 15.0」，标签为「配速（长按可改）」。

### 6.2 官方地图 SDK 适配层与 Key 缺失提示

- 新增 `app/src/main/java/org/localroute/app/map/MapProviders.java`：判断 Key 是否存在、生成用户可见说明、把 Key 打码（`abcd…6789`）。
- Key 从 `local.properties` 的 `amapKey=...`（或 `-PamapKey=...`）注入 `BuildConfig.AMAP_KEY`，**不进仓库**；没配置时是空串，构建照常成功。
- 状态只有三种：`KEY_MISSING` / `KEY_PRESENT_SDK_PENDING` / `SDK_ACTIVE`；本版本即使有 Key 也只是「待接入」，因为没引入高德 SDK 依赖——`MapProvidersTest` 专门断言提示文案**不会**声称官方 SDK 已生效。
- 界面行为：切到「高德地图」瓦片源时弹出 `MapProviders.note(...)`，明确写出「现在用的是栅格瓦片、不是官方 SDK、Key 有没有配」。
- 兜底不变：OSM（官方/France/Germany）仍可切换，瓦片探测与不可达提示保留。

### 6.3 这一轮为什么没直接接高德 SDK

接 SDK 需要：开放平台 Key（绑定包名 + 发布版 SHA1）、`com.amap.api.v2.apikey` meta-data、以及 SDK 依赖与 native 库 ABI。前两项依赖用户侧的账号与 Key；在没有 Key 的情况下引入 SDK 只会得到 `INVALID_USER_SCODE` 且增大包体。所以本轮做的是「适配层 + 明确提示」，Key 到位后只需替换 `RouteMapController` 的底图实现，坐标换算（`ChinaShift`）与图层逻辑都不用动。

## 7. 高德 Key 落地情况（2026-10-27 build 6）

- Key 已写入 `local.properties` 的 `amapKey=...`（被 .gitignore 排除，未进库），`BuildConfig.AMAP_KEY` 与 `mapProviders` 已能读到；界面切「高德地图」时提示变为「已配置（d11e…a6da），本版本仍使用栅格瓦片」。
- 试接一次官方 SDK 并撤回：加 `com.amap.api:3dmap:10.0.600`（Maven Central 可解析）+ manifest `com.amap.api.v2.apikey` 占位符后，`assembleDebug` 成功、合并后的 manifest 里 Key 正确、APK 内含 `libAMapSDK_MAP_v10_0_600.so`。
- 撤回的原因：该 SDK 只带 `arm64-v8a`/`armeabi-v7a` 的 so，**没有 x86_64**，本机模拟器（x86_64）无法加载；同时 debug 包从 48 MB 涨到 86 MB、release 预计 +10 MB 以上。在还没替换 MapLibre 渲染路径之前背着这些体积和「只有真机能验」的限制没有收益，所以保留 Key 接入与提示层，SDK 真正接入留到替换渲染引擎的那一版。
- 结论：Key 的**有效性尚未验证**（需要真机或 arm 架构模拟器；`INVALID_USER_SCODE` 只能在 SDK 实际初始化时暴露）。
