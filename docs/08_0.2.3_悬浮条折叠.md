# 0.2.3 悬浮条折叠与版本记录

日期：2026-10-27　版本：0.2.3（versionCode 10）

## 起因

用户反馈两点：① 悬浮条挡住底下的跑步 App，希望默认显示「+」，点开才是完整面板、再点「−」收起；② 第三方跑步软件仍然不把本应用输出的坐标当成真实跑动。

## 折叠面板（已实现）

`app/src/main/java/org/localroute/app/overlay/OverlayPanel.java`：

- 面板结构改为「头部一行 + 内容区」：头部只放折叠按钮，内容区装状态文字、暂停/停止、A/B/C 快捷传送槽位。
- 折叠按钮文案随状态切换：展开时显示「−」，折叠时显示「+」；点击调用 `setCollapsed(!collapsed, true)`。
- 折叠状态存 `SharedPreferences`（`ui` / `overlay_collapsed`），下次打开悬浮条沿用上次的选择。
- 折叠/展开后调用 `WindowManager.updateViewLayout`，窗口立刻按新尺寸重新排布。
- 拖动改为只挂在状态文字上（`statusView.setOnTouchListener(new DragListener())`），不再挂在根布局：挂在根上会把按钮的点击一并吃掉。

模拟器验证：截图 `evidence-emu/66-overlay-expanded.png` 显示展开态（含「−」按钮、暂停/停止、A/B/C）；`evidence-emu/67-overlay-collapsed.png` 与 `68/69` 为同一状态的复现截图。折叠动作本身在无头环境里用 `adb shell input tap` 点击悬浮窗按钮时未能触发（悬浮窗不进入 uiautomator 无障碍树，坐标命中靠目测），**折叠后只剩「+」的实际画面尚未取得截图**，需要用户在真机或模拟器上手动点一下确认。

## 第三方识别（能力边界，未做规避）

- Android 11（API 30）起，`Location.isMock()` 会把通过测试 provider 注入的位置标记为模拟；旧版本对应 `Location.isFromMockProvider()`。这个标记由系统写、第三方应用读，**应用层无法清除**；只有 root / Xposed / 定制 ROM 之类系统级手段才能绕过，那属于规避第三方风控，本项目不做。
- 本应用能做的是"让系统这一层尽量正常"：输出完整 `Location`（经纬度、精度、速度、航向、时间戳）、保持 500ms 节奏、跑圈时按距离给出真实速度而不是 0。系统侧的确认方法已写进安装文档（`dumpsys location` 与定位探针 App 都会显示 `mock` 标记）。
- 目标 App 的 APK 只能用来判断它到底检测了什么（例如是否读 `isMock`、是否校验开发者选项、是否有加速度/步数交叉校验），不能用来绕过检测。用户可以自行反编译查看，本仓库不提供绕过方案。
